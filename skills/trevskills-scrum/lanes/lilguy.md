# Lilguy lane

The orchestrator spawns no subagents (no spec writer, builder, reviewer or approver) and makes the change itself, in the job's own `scrum/<id>` worktree, and lands it through the normal **Merge** squash PR. A job enters this lane in one of three ways:
- **New job** step 3's **Lilguy route** sends a tiny job here when `B lilguy-fit $ID` prints `fit: true`: a job with no `parent` or a `runall` parent (so **Run all** children too), outside a Cloud lane session, that is 1 point on the backlog or that Jev rates trivial with confidence, and whose feature.md has no hard-stop word. A pre-written spec.md does not stop the route.
- `/trevskills-scrum lilguy <id>` (the `lilguy <id>` option of **New job** step 3c's park or of the parked `Terminal batch: project .claude edits` job that `B claude-batch` fills, opened in a Terminal window so Trevor can approve each edit): when the argument is exactly the id of a board job in `needs-human`, set `ID=<id>`, load it like `approve` (`WT`, `BASE`, `DEFAULT`), run `B set --unpause <id> stage=build reason=`, **record your terminal**, then step 1 below, reusing the job's worktree when it has one. Any other id-shaped argument that names no `needs-human` job is refused.
- `/trevskills-scrum lilguy <feature text>` runs **New job** steps 1, 1b and 2 (job, feature.md, base), then step 1 below. It never runs `B lilguy-fit $ID`, because Trevor picked the lane himself.

1. **Worktree.** Run `B set $ID lane=lilguy`, then **New job** step 4. If `.claude/worktrees/scrum-$ID` already exists (a resume), reuse it as `$WT` instead.
2. **Build.** Run `B set $ID stage=build`. Read `$F/project.md` and every convention file it lists, make the change in `$WT` (to `spec.md`'s acceptance criteria when `$F/jobs/$ID/spec.md` exists) and commit it on `scrum/<id>`. When feature.md's `Lane:` line starts `Lane: lilguy — bug, cause pinned:`, first write a test that reproduces the bug, run it to see it fail, commit it alone, then fix and see it pass; check.md names the repro test. When feature.md's `Lane:` line starts `Lane: lilguy — knowledge save` and a fact to save contradicts the target .md or the code, make no edit for that fact and run `B ask $ID 'md contradiction: <the fact to save> vs <what the .md or code says, with its file name>' --a "Save the new fact=rework $ID \"save the new fact and rewrite the line it contradicts\"" --b "Remove this job=abort $ID --cascade" --title MD_CONTRADICTION --recommend <key> '<why>'`, then stop.
3. **Check.** Run `B set $ID stage=check`. In `$WT`, run a minimal check, not the full **Check gate**: only these **Check gate** step 2 commands and its `.env` check, each through the same check lock. **Typecheck** runs as the Check gate runs it. **Test** runs only the tests related to the diff: when the `Test:` command runs jest (it names `jest`, or it is an npm script whose `package.json` script names `jest`), run `npx jest --findRelatedTests --passWithNoTests <files>`, where `<files>` are the `.js/.jsx/.ts/.tsx/.mjs/.cjs` files in `git -C "$WT" diff --name-only --diff-filter=d "$BASE"...HEAD`, and with no such file Test does not run (`Test: skipped, no source file in diff`); any other test runner runs the full `Test:` command. **Lint** follows the Check gate's changed-files rule. No full jest run, no Build, no `B e2e-specs`, E2E command, spec-file run or **Dev migrate**: GitHub CI and the Vercel build still guard merge and deploy, and the full E2E suite runs on main from the serve.py watchdog. Write `$F/jobs/$ID/check.md` in the **Check gate** step 3 format, with `Test: related only` above the jest block, `Build: skipped, lilguy lane` and `E2E: skipped, lilguy lane` in place of their blocks (no `round-N/`; `round` and `limit` stay unset). A `.env` hit is a check failure. Schema files are not stopped here: **Merge**'s schema guard (**Migrate**) handles them.
4. **Route.** On a check failure, fix, commit and re-run step 3. On the 3rd failure, run `B route-check $ID --check-fails 3`. After a pass, run `B route-check $ID`. A non-null `promote` promotes the job (below); it triggers on a 3rd check failure, a binary file, more than 30 added lines, more than 10 files with added lines, or a rules file not named in feature.md. Exception: when the trigger is a line or file count and the diff is mostly deletions, you may keep the job here and append `Kept in lilguy lane: <trigger>` to `$F/jobs/$ID/promoted.md`. A `null` `promote` goes on to step 5.
5. **Merge.** Land through **Merge**. Wherever Merge resumes the builder, make the fix yourself. Merge's **Conflicts** step returns to step 3 here, not to the **Check gate**. The PR uses Merge's no-Merge-summary fallback, with bullets summarising the change, and the body line `Lilguy lane: orchestrator build + check gate, no reviewers. Job files: scrum/jobs/$ID/`. With no decision.md, `Restart:` counts as `none`.

**Promotion.** Run `B set $ID lane=fast` and append `Promoted to fast: <trigger>` to `$F/jobs/$ID/promoted.md`. Keep the worktree and its commits. Then run **New job** step 3 with `WORKTREE=$WT` (its `B lilguy-fit` now says `already on fast lane`), then 3b and 3c, except that `Lane: bigboy` and `Lane: debug` count as `standard`. Skip step 4 and go on at step 5, so the builder continues from the existing commits. From there the **Fast lane** promotions to standard apply.

**Resume.** A lilguy job with a worktree flagged `stalled` re-runs this lane: step 2 for `build`, step 3 for `check`, **Merge** from step 1 for `merging`.

6. End with the **Final report** (job id, stage, PR URL, and for needs-human the reason).
