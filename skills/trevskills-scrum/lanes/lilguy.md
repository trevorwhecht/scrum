# Lilguy lane

The orchestrator spawns no subagents (no spec writer, builder, reviewer or approver) and makes the change itself, in the job's own `scrum/<id>` worktree, and lands it through the normal **Merge** squash PR. A reviewer feature.md asks for is the one exception: spawn it as one Agent call with the override `model: "sonnet"`, since a general-purpose call without it runs on Opus (job 1921: $2.31 of $3.66 for a 17-line docs edit). A job enters this lane in one of three ways:
- **New job** step 3's **Lilguy route** sends a tiny job here when `B lilguy-fit $ID` prints `fit: true`: a job with no `parent` or a `runall` parent (so **Run all** children too), outside a Cloud lane session (a shop run, `SCRUM_SHOP` set, counts as outside), that is 1 or 2 points on the backlog, that Jev rates trivial with confidence, whose feature.md names a file path, or that names none and quotes a text or dollar amount it changes from that 1 to 10 repo files hold (`git grep -lF`), and whose feature.md has no hard-stop word and an estimate (10 added lines per named path) within 30 lines and 10 files. A pre-written spec.md does not stop the route.
- `/trevskills-scrum lilguy <id>` (the `lilguy <id>` option of **New job** step 3c's park or of the parked `Terminal batch: project .claude edits` job that `B claude-batch` fills, opened in a Terminal window so Trevor can approve each edit): when the argument is exactly the id of a board job in `needs-human`, set `ID=<id>`, load it like `approve` (`WT`, `BASE`, `DEFAULT`), run `B set --unpause <id> stage=build reason=`, **record your terminal**, then step 1 below, reusing the job's worktree when it has one. Any other id-shaped argument that names no `needs-human` job is refused.
- `/trevskills-scrum lilguy <feature text>` runs **New job** steps 1, 1b and 2 (job, feature.md, base), then step 1 below. It never runs `B lilguy-fit $ID`, because Trevor picked the lane himself.

Every Bash call is one more turn that re-reads the whole session, about 65k tokens before any work, so run each step's commands and any independent searches together in one call. In step 1's call, run the `read` command `B lilguy-fit` printed (New job steps 2 and 4, **Check gate** steps 2-3, **Merge** steps 3-7), leaving out a `sed` whose file is already whole in the session and the whole command when its output already is; with no `read` (the two `lilguy` entries above, a resume, or none printed), read `lanes/newjob.md` (when it is not already in the session) and only `sed -n '1,/^## Migrate/p' lanes/merge.md` instead. Never read one lane file per call or a part already in the session; when a Bash output comes back as a 2 KB preview with a `Full output saved to:` path, Read that file in the next call and re-run no command whose output it holds (job 1861 re-ran `cat lilguy.md` after its 40.8 KB read was cut); read merge.md's `## Migrate` only when the schema guard sends you there (jobs 1234, 1242, 1248, 1291; trevorhecht-skills 082; boisepartyco 413, 415).
Set `ID` to the full job id the prompt names and run git on the branch as `git -C "$WT"`, so no turn is spent finding the id or retrying a commit (boisepartyco 413).
Every edit of the target repo uses a path under `$WT/`, never `$REPO` (an Edit or Write path starts with `$WT/`; a relative path or a `cd "$REPO"` edit lands in the main checkout, as job 2202's docs edit did).

1. **Worktree.** Run `B set $ID lane=lilguy` (and `B set $ID kind=knowledge` when feature.md's `Lane:` line starts `Lane: lilguy — knowledge save`), then **New job** step 4. If `.claude/worktrees/scrum-$ID` already exists (a resume), reuse it as `$WT` instead. When `$WT` is missing, or `git -C "$WT" rev-parse --is-inside-work-tree` fails, or its branch is not `scrum/$ID`, run `B ask $ID 'blocked: worktree missing or unusable' --kind blocked --a "Send back with a note=rework $ID \"make the most reasonable call on the blocker and record it as a Ruling in build.md\"" --b "Put back on the backlog=abort $ID --requeue" --c "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend <key> '<why>'` and stop; never fall back to editing `$REPO`.
2. **Build.** Run `B set $ID stage=build`. When feature.md asks for a new E2E test (a new case in an `e2e/` spec, not a fix to an existing one) or a measured run (a full E2E run, a peak RSS, timing or cache table), make no edit here: run **Promotion** now with the trigger `new E2E test` or `measured run`, adding the `Complex: no — promoted from lilguy` line when feature.md has no `Complex:` line, since step 3 runs no spec file (job 1942 wrote and ran its 59-line spec by hand in this session, $1.80 of $1.98 over 41 Bash calls; job 1937 ran its full E2E and cache runs here, $1.93 of $2.20 over 47 Bash calls). Read `$F/project.md` and every convention file it lists, make the change in `$WT` (to `spec.md`'s acceptance criteria when `$F/jobs/$ID/spec.md` exists) and commit it on `scrum/<id>`. Before editing text in an agents, lanes or SKILL.md file, read the size-cap and adjacency pins in `tests/test_contracts.py` for that file and grep that test file for a phrase of each line you trim, so the add and the trim land in one edit that fits the cap by `wc -c` before any contract-test run (job 1523: 31 Bash calls, $1.34 for one bullet). Never start parallel copies of a test run to make CPU load, even to prove a load-flaky test fixed; mock the load or the timing instead (job 1713). When feature.md's `Lane:` line starts `Lane: lilguy — bug, cause pinned:`, first write a test that reproduces the bug, run it to see it fail, commit it alone, then fix and see it pass; check.md names the repro test. Before any fix, grep every caller of the function it changes and every dashboard reading of the same rule: a caller whose argument routes around the fix (a `prefer=`) or a reading that still shows the old rule gets the same fix in this job, or check.md says why not (jobs 1182, 1184). When feature.md's `Lane:` line starts `Lane: lilguy — knowledge save` and a fact to save contradicts the target .md or the code, make no edit for that fact and run `B ask $ID 'md contradiction: <the fact to save> vs <what the .md or code says, with its file name>' --a "Save the new fact=rework $ID \"save the new fact and rewrite the line it contradicts\"" --b "Remove this job=abort $ID --cascade" --title MD_CONTRADICTION --recommend <key> '<why>'`, then stop. When the change is blocked on another board job (named by id or number, e.g. its doc describes code that job has not merged), run `B wait-on $ID <that id> --then "approve $ID"` and stop: the worktree and its commits stay, and serve.py wakes the job once the blocker merges. When no board job is named or `wait-on` exits non-zero, run `B ask $ID 'blocked: <first reason line>' --kind blocked --a "Send back with a note=rework $ID \"make the most reasonable call on the blocker and record it as a Ruling in build.md\"" --b "Put back on the backlog=abort $ID --requeue" --c "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend <key> '<why>'` and stop.
3. **Check.** Run `B set $ID stage=check`. In `$WT`, run a minimal check, not the full **Check gate**: only these **Check gate** step 2 commands and its `.env` check, each through the same check lock, in one `run_in_background` call waited on as SKILL.md's **Headless sessions block** says. A `buildlock: waiting for the build lock` line means the check is queued (up to 30 min, then exit 124), so never poll its pid or read buildlock.py while it waits (job 1736). **Typecheck** runs as the Check gate runs it. **Test** does not run (`Test: skipped, lilguy lane`), except that a `Lane: lilguy — bug, cause pinned:` job runs only its repro test (`Test: repro only`), plus every test file that names a file its diff changes (`grep -l <basename>` over the test directories). **Lint** follows the Check gate's changed-files rule. No other test run, no Build, no `B e2e-specs`, E2E command, spec-file run or **Dev migrate**: GitHub CI and the Vercel build still guard merge and deploy, and the full E2E suite runs on main from the serve.py watchdog. Write `$F/jobs/$ID/check.md` in the **Check gate** step 3 format, with `Build: skipped, lilguy lane` and `E2E: skipped, lilguy lane` in place of their blocks (no `round-N/`; `round` and `limit` stay unset). A `.env` hit is a check failure. Schema files are not stopped here: **Merge**'s schema guard (**Migrate**) handles them.
4. **Route.** On a check failure, fix, commit and re-run step 3. On the 3rd failure, run `B route-check $ID --check-fails 3`. After a pass, run `B route-check $ID`. A non-null `promote` promotes the job (below); it triggers on a 3rd check failure, a binary file, more than 30 added lines, more than 10 files with added lines, or a rules file not named in feature.md. Exception: when the trigger is a line or file count and the diff is mostly deletions or changes only `.md` files under `docs/`, you may keep the job here and append `Kept in lilguy lane: <trigger>` to `$F/jobs/$ID/promoted.md`. Never cut the diff's text to get under a count (job 1927 cut its docs save from 34 to 29 added lines over more calls). A `null` `promote` goes on to step 5. `B route-check` never promotes a `Lane: lilguy — mechanical` job (renames, config switches, docs) on its line or file count.
5. **Merge.** Land through **Merge**. Wherever Merge resumes the builder, make the fix yourself. Merge's **Conflicts** step returns to step 3 here, not to the **Check gate**. The PR uses Merge's no-Merge-summary fallback, with bullets summarising the change, and the body line `Lilguy lane: orchestrator build + check gate, no reviewers. Job files: scrum/jobs/$ID/`. With no decision.md, `Restart:` counts as `none`.

**Promotion.** Run `B set $ID lane=fast` and append `Promoted to fast: <trigger>` to `$F/jobs/$ID/promoted.md`. When the trigger is a line or file count and feature.md has no `Complex:` line, add the line `Complex: no — promoted from lilguy` after its first line, so step 5's builder runs on Sonnet (job 1769). Keep the worktree and its commits. Then run **New job** step 3 (its `B lilguy-fit` now says `already on fast lane`, and its fast-lane rule copies feature.md to spec.md, so spawn no spec writer; job 1819), then 3b and 3c, except that `Lane: bigboy` and `Lane: debug` count as `standard`. Skip step 4 and go on at step 5: spawn the builder even when the commits look complete, so it continues from them and writes build.md (job 1428 skipped it, and round 1 asked for the missing build.md). On promotion the lilguy check.md never stands in for the **Check gate**: rerun it in full for round 1 and overwrite check.md, so a `Test:` that is not jest runs whole test files per the **Fast lane Test** rule (jobs 1403 and 1406 kept `-k` subsets, and 1406 left main red until job 1409). From there the **Fast lane** promotions to standard apply. A `measured run` job's builder runs only the spec files feature.md names, and no one runs the whole E2E suite for it, so its Check gate writes `E2E: skipped, fast lane` (job 2166's session ran two full `--workers=3` runs that serve.py stopped for memory, at 16 and 19 GB).

**Resume.** A lilguy job with a worktree flagged `stalled` re-runs this lane: step 2 for `build`, step 3 for `check`, **Merge** from step 1 for `merging`.

6. End with the **Final report** (job id, stage, PR URL, and for needs-human the reason).
