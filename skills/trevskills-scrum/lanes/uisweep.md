# UI sweep

A later visual re-check of the screens merged on main. serve.py's watchdog (`ui_sweep_tick`, after `e2e_full_tick`, on the same 5-merges-or-24-h rule) writes `targets.json` and starts this session headless with `SWEEP_DIR=<dir>`, `PROJECT=<scrum>/project.md` and `REPO=<main checkout>` in the prompt. No human is watching: never ask, never edit code, never commit, push or merge. `B` is `python3 ~/.claude/skills/trevskills-scrum/board.py --dir <the folder holding PROJECT>`.

`SWEEP_DIR/targets.json` is `{"since", "head", "targets": [{"path", "jobs", "marked", "why"}]}`: each screen the merges since the last sweep changed, the merged job ids (or `commit <sha7>`) that touched it, and the approver's `## UI sweep` screens (`marked: true`) first. Every target ends up in `SWEEP_DIR/review.md` as `- ok <path>`, `- [blocking] <path> — <finding> — <png>` or `- Unrendered: <path> — <why>`; `B ui-sweep-record` files any target the review leaves out as unrendered, so no screen is skipped silently.

1. **Dev server.** Start PROJECT's `Dev command:` from `REPO` under lanes/review.md's **Shared dev server** rules: a free port that is never 8765 or 3001, `PORT=<port> NEXTAUTH_URL=http://localhost:<port>`, output to `SWEEP_DIR/dev.log`, the PID and port recorded, serve.py `$T` isolation when the command is serve.py, and its **Probe** (the root page only, as there is no diff). When `PROJECT`'s Notes name a database container, start it first as **Database.** in `agents/scrum-review-ui.md` says. A server that never answers makes every target `- Unrendered: <path> — dev server did not start: <why>`: write that review.md yourself and go to step 4.
2. **Render.** Resolve each target to a URL path. A path that does not start with `/` (the approver named a screen, not a route) is found in `REPO`'s routes, else it is `Unrendered`. A dynamic `[param]` route gets a real dev row id (read one from a list page or the dev database the Notes name; never port 3001 or a production env file), else it is `- Unrendered: <path> — no dev row for <param>`. Then, in `targets.json` order (marked first), run `python3 ~/.claude/skills/trevskills-scrum/render.py http://localhost:<port> "$SWEEP_DIR/render-<n>" <paths>` with Bash timeout 300000, at most `RENDER_CAP` (board.py, 8) paths per call, so a long list takes several calls, each into its own `render-1`, `render-2`, … folder (render.py empties its folder first); add `--cookies "$REPO/<path>"` before the paths when `PROJECT` has a `- Render auth: <repo-relative path>` line. A non-zero exit or a page that is not `ok` in its `manifest.json` leaves those targets for the reviewer to mark `Unrendered` with the manifest's status.
3. **Review.** Spawn `scrum-review-ui` and wait for it. Prompt:
   ```
   SWEEP_DIR=<SWEEP_DIR>
   PROJECT=<PROJECT>
   Sweep mode: judge every ok page in SWEEP_DIR/render-*/manifest.json and write SWEEP_DIR/review.md.
   ```
   Add your own `- Unrendered: <path> — <why>` line to review.md for each target step 2 could not render that the reviewer did not list. If review.md is still missing or its first line is not `VERDICT: PASS` or `VERDICT: CHANGES`, spawn it once more.
4. **Record.** Run `B ui-sweep-record "$SWEEP_DIR/review.md"`. It files each `[blocking]` line and each unrendered or unlisted target as a p4 Trevor backlog item and closes `scrum/ui-sweep.json`. When review.md is still missing, write it with one `- Unrendered: <path> — sweep review missing` line per target first, so the run still files them. A refusal (`not the current UI sweep`) means a newer sweep owns the record: file nothing and stop.
5. **Stop the server** on every outcome, including a failed probe or a refused record: `kill <recorded PID>`, then `lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill` for any child still listening, then `rm -rf "$T"` when step 1 made one.
