# UI sweep

A later visual re-check of the screens merged on main. serve.py's watchdog (`ui_sweep_tick`, after `e2e_full_tick`, on the same 5-merges-or-24-h rule) writes `targets.json` and starts this session headless at nice 19 (job sessions run at 10), only while no job holds or waits on `check.lock` or `build.lock` unless the last sweep is over 24 h old, with `SWEEP_DIR=<dir>`, `PROJECT=<scrum>/project.md` and `REPO=<main checkout>` in the prompt. No human is watching: never ask, never edit code, never commit, push or merge. `B` is `python3 ~/.claude/skills/trevskills-scrum/board.py --dir <the absolute path of the folder holding PROJECT>`, never a relative `--dir scrum`, which logs the sweep as `repo=.` in every project's digest.

`SWEEP_DIR/targets.json` is `{"since", "head", "targets": [{"path", "jobs", "marked", "why"}]}`: each screen the merges since the last sweep changed, the merged job ids (or `commit <sha7>`) that touched it, and the approver's `## UI sweep` screens (`marked: true`) first. Every target ends up in `SWEEP_DIR/review.md` as `- ok <path>`, `- [blocking] <path> — <finding> — <png>` or `- Unrendered: <path> — <why>`; `B ui-sweep-record` files any target the review leaves out as unrendered, so no screen is skipped silently.

1. **Dev server.** **Install.** When the lockfile changed between `targets.json` `since` and `head`, run PROJECT's `Install:` command in `REPO` first, so a dependency a merged job added is there: the lockfile is `package-lock.json`, else `pnpm-lock.yaml`, `yarn.lock` or `bun.lockb`, whichever exists in `REPO`, and it changed when `git -C "$REPO" diff --quiet <since> <head> -- <lockfile>` exits non-zero; an unchanged lockfile skips the install. No server of this sweep is running yet, as this comes before the start below. A failed install does not stop the sweep: append its output to `SWEEP_DIR/dev.log` and go on to the dev server and its **Probe**, which decides whether targets are `Unrendered`. Then start PROJECT's `Dev command:` from `REPO` under lanes/review.md's **Shared dev server** rules: a free port that is never 8765 or 3001, `PORT=<port> NEXTAUTH_URL=http://localhost:<port>`, output to `SWEEP_DIR/dev.log`, the PID and port recorded, serve.py `$T` isolation when the command is serve.py, and its **Probe** (the root page only, as there is no diff). When `PROJECT`'s Notes name a database container, start it first as **Database.** in `agents/scrum-review-ui.md` says. A server that never answers makes every target `- Unrendered: <path> — dev server did not start: <why>`: write that review.md yourself and go to step 5.
2. **Render.** Resolve each target to a URL path. A path that does not start with `/` (the approver named a screen, not a route) is found in `REPO`'s routes, else it is `Unrendered`. A dynamic `[param]` route gets a real dev row id (read one from a list page or the dev database the Notes name; never port 3001 or a production env file), else it is `- Unrendered: <path> — no dev row for <param>`. **Auth paths.** Every auth line's path (`- Render auth:`, `- Customer render auth:`, `- Employee render auth:`) is written relative to a job worktree, so strip every leading `../` and use `$REPO/<rest>` (`../../../playwright/.auth/admin.json` becomes `$REPO/playwright/.auth/admin.json`); a path with no leading `../` is used as `$REPO/<path>`. Use that resolved path for `--cookies` and for the **Render auth refresh** check. A route gated to the customer role (`REPO`'s middleware or layout role checks, for example `/account`) is never passed to render.py with the `- Render auth:` session: when `PROJECT` has a `- Customer render auth: <repo-relative path>` line, render those routes in their own calls with `--cookies` and the resolved path after the same **Render auth refresh**, else each is `- Unrendered: <path> — needs customer session`. A route gated to the employee role (`/employee/*`) is handled the same way with `- Employee render auth: <repo-relative path>`: its own calls with `--cookies` and the resolved path after the same **Render auth refresh**, else each is `- Unrendered: <path> — needs employee session`. Then, in `targets.json` order (marked first), run `python3 ~/.claude/skills/trevskills-scrum/render.py http://localhost:<port> "$SWEEP_DIR/render-<n>" <paths>` with Bash timeout 600000, at most `RENDER_CAP` (board.py, 8) paths per call, so a long list takes several calls, each into its own `render-1`, `render-2`, … folder (render.py empties its folder first); add `--cookies` with the resolved `- Render auth:` path before the paths when `PROJECT` has a `- Render auth: <repo-relative path>` line. Run the **Render auth refresh** bullet of `lanes/review.md` step 2 first, in `REPO`. A non-zero exit or a page that is not `ok` in its `manifest.json` leaves those targets for the reviewer to mark `Unrendered` with the manifest's status.
3. **Review.** Spawn `scrum-review-ui` and wait for it. Prompt:
   ```
   SWEEP_DIR=<SWEEP_DIR>
   PROJECT=<PROJECT>
   Sweep mode: judge every ok page in SWEEP_DIR/render-*/manifest.json and write SWEEP_DIR/review.md.
   ```
   Add your own `- Unrendered: <path> — <why>` line to review.md for each target step 2 could not render that the reviewer did not list. If review.md is still missing or its first line is not `VERDICT: PASS` or `VERDICT: CHANGES`, spawn it once more.
4. **Stop the server** on every outcome, including a failed probe: `kill <recorded PID>`, then `lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill` for any child still listening, then `rm -rf "$T"` when step 1 made one. Do this before step 5, so a closed `ui-sweep.json` always means the dev lock is free.
5. **Record.** First change each `- [blocking] <path> — <finding> — <png>` line whose problem an open `- [ ] UI sweep: <path>:` line in `scrum/backlog.md` already names, in any wording, to `- ok <path> — known {#id}`, so a sweep never files a known finding twice. Run `B ui-sweep-record "$SWEEP_DIR/review.md"`. It files each `[blocking]` line and each unrendered or unlisted target as a p4 Trevor backlog item and closes `scrum/ui-sweep.json`. An `- Unrendered:` line whose reason says the page timed out under load files nothing: its path is kept in `ui-sweep.json` `retry` and the next sweep's targets include it. When review.md is still missing, write it with one `- Unrendered: <path> — sweep review missing` line per target first, so the run still files them. A refusal (`not the current UI sweep`) means a newer sweep owns the record: file nothing and stop.
