# Edit lane

Every edit Trevor makes (an Instagram reel, a motion animation, vector art, PhotoCraft photo work) runs as a job of the `edit` project (`~/Developer/vid-img-editing`, a plain folder with no git: its project.md says `- Git: none`, and nobody runs `git init` there). One lane, four kinds, each with its own file; this file is the shared flow. The folder lives outside git, so this lane has no worktree, branch, PR, Check gate, Review or Merge, and only Trevor's approval ends a job.

**Kind files.** Read `$HOME/.claude/skills/trevskills-scrum/lanes/<kind>.md` for the job's kind (`<kind>` is `edit-reel`, `edit-animation`, `edit-vector` or `edit-photo`) and no other file of that pattern.

1. **Route.** A job whose `$F/jobs/$ID/feature.md` has a line `Kind: <kind>` runs this lane: the first line matching `^Kind: (edit-reel|edit-animation|edit-vector|edit-photo)\s*$`, anywhere in the file (a backlog item's first line included), which `board.edit_kind` reads. So does every job of a project whose project.md has `- Git: none`. Before anything else in New job, run `B set $ID lane=edit kind=<kind>` (ahead of the lilguy fit, Askme, Base and the spec writer; with no valid kind, `B set $ID lane=edit` alone, then **No kind**), then follow this file and the kind's file (**Kind files** below). For every command on the job (new, resume, rework, approve) this lane replaces New job, the spec writer, the Check gate, Review and Merge: there is no worktree, branch, PR, Check gate, Review or Merge, and it never spawns a scrum agent or a stand-in for one. Edit jobs run only on the main Mac (the shop Mac's `## Cannot run` list names each `Kind:` line).
   - **No kind:** a job whose kind's file says it is not built yet, and in a project whose project.md has `- Git: none` a job whose feature.md has no valid `Kind:` line (one of the four kinds; `Kind: reel` or `Kind: edit-movie` is not), starts nothing. Write why to stop.md in the job folder, then run `B ask $ID 'blocked: this edit job does not name a kind that can be made yet, so nothing was started. Why is in the stop.md tab. Send the kind (edit-reel, edit-animation, edit-vector or edit-photo), or remove the job?' --a "Send back with a note=rework $ID \"Kind: <kind>\"" --b "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend <key> '<why>'` and stop.
   - A rework note with a `Kind: <kind>` line writes that line into feature.md in place of any old `Kind:` line, then this step runs again.
2. **Agents.** Build by `edit-builder` (opus), review by a fresh `edit-reviewer` each round (opus: a new Agent every round, never the session that built the edit), and `edit-logger` (sonnet) logs a reel's footage in the batches this session spawns for the builder (an agent cannot spawn an agent). Each prompt names the kind, the work folder, the job folder and the step. The reviewer's prompt lists the files and never the builder's reasons: never paste the builder's reply into it.
   - **Missing agent:** an Agent call for one of these three that fails with `Agent type '<name>' not found` never falls back to another agent or to doing the step yourself: retry once after about 5 seconds, then stop with the `AGENT_MISSING` ask in **Routing** (`lanes/routing.md`), naming that agent.
3. **Ledger.** Each kind keeps a job ledger in the job folder, named in its file and created on the first run. Append to it after every step; never rewrite an earlier line. Each of Trevor's notes goes word for word into the kind's rules file and the job ledger, with the round it answers, the same day.
   - **Resume:** a resume, re-run, rework or approve reads the job ledger first and continues at its last unfinished step: it never re-asks an approved storyboard, never redoes a step the ledger records as done, and never reuses a review number.
4. **Build.** `B set $ID stage=build` and spawn `edit-builder` with the prompt in the kind's file. A `BLOCKED:` last line: write its reason to stop.md in the job folder and run `B ask $ID 'blocked: the edit builder could not go on. Its reason is in the stop.md tab. Send notes to try again, or remove the job?' --a "Send back with a note=rework $ID \"<what to change>\"" --b "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend <key> '<why>'` and stop.
5. **Review.** `B set $ID stage=review` and spawn a fresh `edit-reviewer` with the prompt in the kind's file. It writes `$F/jobs/$ID/review-N.md` (`N` counts the job's reviews from 1, one more than the highest in the ledger) whose first line is `RECUT` or `PASS`, then `must fix`, `left out` and `stitch chances`; a missing file or first line counts as `RECUT`. It never edits the work. A `RECUT` sends its notes back to step 4 for the next round. After the third `RECUT` in a row on the same cut the builder stops trying, and the reviewer's notes go to Trevor on the card: the kind's approval ask carries the latest cut with those notes.
6. **Approval.** Each kind asks Trevor with `--title EDIT_APPROVE`; its file holds the ask. The step right before each approval ask that has a file to open writes one line `View: <app> <absolute path>` to `$F/jobs/$ID/view.md`, replacing any older file: animation `QuickTime Player` plus the master's absolute path; reel final `Edits` with no path (Edits takes no file); vector `VectorCraft` and photo `PhotoCraft`, each plus the file's absolute path. The dashboard's View button runs `open -a` on that line. Notes are never approval: a rework note starts the next build round with the note in the ledger. Only Trevor's approval ends the job: a reviewer `PASS` never does. On approval keep one current version (`~/.claude/rules/one-current-version.md`, the way the kind's file says), then run `B set $ID stage=done`.
7. **Stops.** Every block or question is a `B ask`, never a silent stop: a run that cannot carry on ends with **No kind**, step 4's ask or the kind's own ask, naming what it hit.
8. **Finish.** The final report gives the job id, the kind, the stage, the version Trevor approved and where it was copied, or, for needs-human, the question and the next command (`approve <id>` or `rework <id> "<notes>"`). There is no PR URL.
