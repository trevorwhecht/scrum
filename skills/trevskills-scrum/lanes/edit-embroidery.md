### edit-embroidery

Embroidery digitizing made with the digitize skill (`$HOME/.claude/skills/trevskills-digitize/SKILL.md`). Trevor approves every version. No MCP server is loaded: the builder uses Bash only (Ink/Stitch headless plus Python), so `EDIT_MCP` has no entry for this kind. One `edit-builder` makes the file and checks it; no `edit-reviewer` is ever spawned for this kind.
1. **Folder.** The job's feature.md names the source art file and a design name. FOLDER is `~/Developer/vid-img-editing/digitizing/scripts/digitize-<name>/`; the builder makes it when it does not exist. The job ledger is `$F/jobs/$ID/embroidery.md`. The kind's rules files are the skill's SKILL.md and `~/Developer/vid-img-editing/digitizing/notes/embroidery-digitizing.md`, both read in full by the builder.
   - **Bad folder:** when FOLDER is not under `~/Developer/vid-img-editing/digitizing/`, or feature.md names no source art file, or that file is missing on disk, start nothing. Write the path and why to stop.md in the job folder, then run the shared step 4 ask (`BUILDER_BLOCKED`) and stop.
   - **No garment:** when neither feature.md nor the ledger's "Trevor's notes" names the garment (and, for a hat, structured or unstructured), start nothing. Write to stop.md which garment is missing and the two or three usual answers, then run the shared step 4 ask (`BUILDER_BLOCKED`) and stop. A rework note naming it goes into the ledger and the run goes on. (Both Necessity caps were built for a structured cap; Trevor's were unstructured.)
2. **Ledger.** `embroidery.md`, created on the first run: `# Embroidery ledger`, then `## Versions` (`- v<V>: <file's absolute path> — check PASS | check MISS — Trevor: pending | notes | approved`), `## Checks` (`- v<V> check <n>: PASS | MISS`, then one line per End check item with its measured number; an item that failed starts with `MISS`) and `## Trevor's notes` (`- <ISO time> (v<V>): <his note, word for word>`). Each note is also copied word for word into `~/Developer/vid-img-editing/digitizing/notes/embroidery-digitizing.md`. The next version is one more than the highest `v<V>` in the ledger. An older ledger's `## Reviews` section stays as it is: add `## Checks` after it. An `approve` means the newest version.
3. **Build.** `B set $ID stage=build`. Spawn `edit-builder` and wait for it, with this prompt:
   ```
   KIND: edit-embroidery. Step: build. JOB_DIR: <JOB_DIR> (job ledger embroidery.md). FOLDER: <FOLDER>. Brief: <JOB_DIR>/feature.md. Follow
   $HOME/.claude/skills/trevskills-digitize/SKILL.md and ~/Developer/vid-img-editing/digitizing/notes/embroidery-digitizing.md. Make everything, the stitch
   files included, in FOLDER; put throwaway tools (Ink/Stitch, the venv) and renders in <FOLDER>/out/. The design is the art's own size unless feature.md says otherwise. The garment is the one named in feature.md or in the newest note that names one.
   Make the DST and its editable SVG (a PES only when feature.md or a note asks), and out/preview.png: the sewn thread drawn over the art with the size in inches on it. After the audit passes, make the PDF worksheet in FOLDER with
   `python -I ~/Developer/vid-img-editing/digitizing/scripts/worksheet.py <the DST> --title "<Name>" --garment "<Garment>"` (Name and Garment from feature.md; it writes `<DST stem>.pdf` beside the DST), and run it again after every rebuild. Apply every note in the ledger's "Trevor's notes" section. When the file is built, run the skill's "End check" list on the finished DST read back
   from disk and write it to the ledger's `## Checks`; fix every item that failed and run the whole list again, at most 3 check rounds. Last line of your reply: the DST's absolute
   path, or BLOCKED: <reason>.
   ```
   A `BLOCKED:` line takes the shared step 4 ask.
4. **Check.** No agent is spawned and stage stays `build`. The session reads only the ledger's newest check for this `v<V>`: a first line `PASS` with no `MISS` item goes to step 5's passed ask; a `MISS`, or no check written for this `v<V>`, goes to step 5's capped ask. It never measures or fixes anything itself.
5. **Version round.** Each version is recorded in the ledger. The step right before the ask writes `$F/jobs/$ID/view.md` as one line `View: Preview <absolute path of out/preview.png>`, replacing any older view.md (the dashboard's View button runs `open -a` on it), and `$F/jobs/$ID/preview.md` with one `- <absolute path>` line, that same PNG, replacing any older preview.md (the dashboard shows it in the stop box). It also writes stop.md in the job folder: the size in inches, stitch count, trims, longest stitch, the audit result, the check's lines with the MISS lines first, and that no file is ready for a run before a test sew-out. Then ask Trevor:
   - Passed: `B ask $ID 'embroidery edit: a new version passed its end check. The preview is open from the View button and the numbers are in the stop.md tab. Approve it, or send notes?' --a "Approve this version=approve $ID" --b "Send back with a note=rework $ID \"<your notes on this version>\"" --c "Remove this job=abort $ID --cascade" --title EDIT_APPROVE --recommend <key> '<why>'` and stop.
   - Capped: `B ask $ID 'embroidery edit: the builder finished this version but its end check still has misses. They are at the top of the stop.md tab.' --a "Approve this version anyway=approve $ID" --b "Send back with a note=rework $ID \"<your notes on this version>\"" --c "Remove this job=abort $ID --cascade" --title EDIT_APPROVE --recommend <key> '<why>'` and stop.

   His notes start the next build round (step 3, version `v<V>` plus one), and only his approval ends the job: a passing check never does.
6. **One current version.** Follow `~/.claude/rules/one-current-version.md` when it exists: on a new build round move the older versions to the Trash (`mv <file> ~/.Trash/`, never `rm`) and keep one current file; move `<FOLDER>/out/` to the Trash on approval. On Trevor's approval, before `B set $ID stage=done`: zip any file the delivery replaces into `~/Desktop/ArtFiles/Embroidery/Archivve/<Name>-<Garment>-archive.zip` (`zip -9 -m`), copy the DST, SVG and PDF (and the PES when asked) to `~/Desktop/ArtFiles/Embroidery/<Name>-<Garment>/`, check each copy with `cmp`, `ls` the folder and record it in the ledger. Nothing is written to the Desktop before approval. Then run `B set $ID stage=done`.
