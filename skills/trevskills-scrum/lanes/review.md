# Review (WAIT FOR ALL)

If the job's `lane` is `fast`, see **Fast lane** instead of this section.

1. Run `B set $ID stage=review`. Write `git -C "$WT" rev-parse HEAD` to `round-$N/head.txt`.
2. **Which reviewers run.** Run `B review-plan $ID`, adding `--incremental` only on a round `N >= 2` that this session started through step 5's `CHANGES` route (never after the Approve `REWORK` route, the Merge **Conflicts** step, or in a resumed session that can't tell how the round started). It decides incremental re-review or full review, writes the carried-forward and skip files into `round-$N/` before any spawn, and prints `{"spawn": [...], "since": ...}`. `since` is the SINCE sha on an incremental round and `null` on a full one; on a full round a reviewer missing from `spawn` was skipped (security: no sensitive files in diff; ui and ux: no `UI globs` file in diff, decided from the diff, never from the spec's `UI surface:` line).
   - **Jev gate (additive only).** Only when `since` is `null` and at least one of `security`, `ui`, `ux` is missing from `spawn`, ask `reviewer-security` (security missing) and/or `reviewer-ui` (ui and ux missing). Run each with Bash timeout 90000:
     ```bash
     { git -C "$WT" diff --stat "$BASE"...HEAD | tail -1; git -C "$WT" diff --name-only "$BASE"...HEAD; } | tr '\n' ' ' | python3 ~/.claude/skills/trevskills-scrum/jev-gate.py <reviewer-security|reviewer-ui> $F/jobs/$ID
     ```
     Output `add` means the gate's 0.7 cutoff was met: delete that skip file and add the reviewer back to `spawn` (security; or both ui and ux). Output `skip`, anything else, an error or a timeout leaves the skips. Jev never removes a reviewer, and is never consulted in the fast lane or for carried-forward reviewers.
   - **Shared dev server (once per round, after the skips and the Jev gate above).** Start it only when all of these hold: at least one of `ui` / `ux` is in step 2's `spawn` after the Jev gate; at least one file in `git -C "$WT" diff --name-only "$BASE"...HEAD` matches `UI globs`; and `project.md`'s `Dev command:` is present and not `none`. When any of these fails, start nothing, write no `dev-url.txt` and pass no `DEV_URL`. Otherwise:
     - Pick a free port that is never 3001 (e.g. `python3 -c 'import socket; s=socket.socket(); s.bind(("",0)); print(s.getsockname()[1])'`, picked again if it prints 3001). Start the server exactly once this round, in the background, from `$WT`: `(cd "$WT" && exec env PORT=<port> nohup <Dev command> >> "$F/jobs/$ID/round-$N/dev.log" 2>&1 < /dev/null) & echo $!`, and record that PID and the port.
     - **serve.py** (`Dev command:` contains `serve.py`): the port is also never 8765. Run `T=$(mktemp -d)` and `mkdir -p "$T/.claude" "$T/.claude/trevskills-scrum"`, write `projects.json` there as a JSON list holding only `$WT`, then start `(cd "$WT" && exec env HOME="$T" CLAUDE_HOME="$T/.claude" nohup python3 skills/trevskills-scrum/serve.py --port <port> >> "$F/jobs/$ID/round-$N/dev.log" 2>&1 < /dev/null) & echo $!` instead, and record `$T` too.
     - **Probe**, polling every 2 s. It counts as reachable only when both succeed within 60 seconds of the start: (a) `curl -s -o /dev/null -w '%{http_code}' http://localhost:<port>/` returns `200`; (b) one GET to a data API path returns a 2xx status. The API path is the first `/api/...` path the diff references (`git -C "$WT" diff "$BASE"...HEAD | grep -oE '/api/[A-Za-z0-9_./-]*' | head -1`), otherwise the first `/api/...` path the served root page references (the same `grep` over `curl -s http://localhost:<port>/`). When neither has an `/api/` path, skip (b) and record `no API path to probe` in `round-$N/dev.log`.
     - On success write `round-$N/dev-url.txt` containing exactly `http://localhost:<port>`. On failure write `round-$N/dev-url.txt` as `unreachable: <why>`, stop the server as in step 4's last bullet, and pass no `DEV_URL`; the ui/ux reviewers then start their own servers.
3. Spawn **in ONE message**, in the background, exactly the reviewers in step 2's `spawn`, each as `scrum-review-<role>` (`scrum-review-security`, `scrum-review-ux`, `scrum-review-ui`, `scrum-review-code`). In the same message, also spawn `scrum-review-e2e` when `project.md` has an `E2E:` line that isn't `none` and any file in `git -C "$WT" diff --name-only "$BASE"...HEAD` matches `UI globs`; it writes `round-$N/review-e2e.md`, overwriting any file the **Check gate** E2E triage left. It is never carried forward and never skipped on an incremental round when those conditions hold. The orchestrator never spawns `scrum-review-e2e` when `project.md` has no `E2E:` line or the line is `none`. Whenever it is not spawned, first run `rm -f "$F/jobs/$ID/round-$N/review-e2e.md"`. Each gets the 5 lines with `ROUND=$N` plus `Review this round. Write only your own review file.` When `since` is non-null, each `spawn` reviewer also gets `SINCE=<since>` and `Re-review: verify each blocking finding in JOB_DIR/round-<N-1>/review-<role>.md against git diff SINCE..HEAD.` When `round-$N/dev-url.txt` holds a URL (not `unreachable: ...`), the `scrum-review-ui` and `scrum-review-ux` spawns, and any step 4 re-spawn of them, also get the extra prompt lines `DEV_URL=<url>` and `DEV_PID=<pid>` (step 2's PID); no other reviewer gets either. No `model:` override is passed to any reviewer.
   - **Move-only refactor.** On a full-review round (never an incremental re-review), after step 2, run `B move-ratio $ID`. When it exits 0 and its `ratio` is `>= 0.9` (nearly every added line is one git marks as moved), add the line `MOVE_ONLY=yes` to the prompts of `scrum-review-code`, `scrum-review-ui` and `scrum-review-ux`, for whichever of them are spawned; never `scrum-review-security`. A non-zero exit or unparseable output means no MOVE_ONLY line. A reviewer missing from step 2's `spawn` stays skipped. Re-run it every full-review round. `review-plan` never skips ui or ux because a diff is mostly deletions: when a `UI globs` file changes, they render the page and confirm the removed element is absent. Security still follows the sensitive-path rule.
4. **WAIT FOR ALL.** Do nothing else until every spawned reviewer has completed. Then run `B sync $ID`.
   - `complete` must be `true`. If it isn't, `missing` lists the absent files: re-spawn only the reviewers named in `missing`, once. If a file is still missing after the re-spawn, write that file yourself as `VERDICT: CHANGES` plus `Reviewer produced no output.`, then run `B sync $ID` again.
   - `review-e2e.md` is optional to `B sync`, so it never appears in `missing`. When you spawned `scrum-review-e2e` this round and `round-$N/review-e2e.md` is absent, re-spawn it once; if it is still missing, write it yourself as `VERDICT: CHANGES` plus `Reviewer produced no output.`, then run `B sync $ID` again. `invalid` may name `e2e`, handled like the others.
   - If `invalid` is non-empty, delete those files and re-spawn those reviewers, once. If they come back invalid again, treat them as CHANGES.
   - **Never resume the builder mid-round.**
   - **Stop the shared server.** Once this WAIT FOR ALL is finished, re-spawns included, and before step 5 routes, stop the server that step 2's **Shared dev server** bullet started: `kill <recorded PID>`, then `lsof -ti tcp:<port> -sTCP:LISTEN | xargs kill` for any child still listening on the port, then `rm -rf "$T"` if step 2 made one (also on a failed probe). Do this on every route out of step 4, including a stop or a needs-human, and skip it only when no server was started this round.
5. Route:
   - `verdict` is `PASS` on a **clean round**: go straight to **Merge**. Spawn no approver; there is no decision.md. Run `B route-check $ID`, adding `--clean-start` only when this session knows the round was not started by the Merge **Conflicts** step; it is a clean round only when its `clean_round` is `true` (it checks the lane, `N` = 1, `round-1/check.md` and all four reviews passing with skip files counted, no `round-1/review-*.md` line starting `Rendered: blocked`, so an environment-blocked render always goes to **Approve**, no schema guard, `.env` or sensitive-path file in the diff, and the spec's `Hard stops:` line being exactly `none`).

     The PR, schema guard and `Restart:` line are handled as in **Fast lane** step 3, with the body line `Clean round: check gate + reviews. Spec and reviews: scrum/jobs/$ID/` instead.
   - `verdict` is `PASS` otherwise (`clean_round` is `false`, or `route-check` exits non-zero): go to **Approve**.
   - `verdict` is `CHANGES` and `round < limit`: resume the builder (see **Sonnet promotion**) with `Review round N has CHANGES: read every review-*.md in JOB_DIR/round-N/, fix blocking findings, commit, update build.md.` (`review-*.md` includes `review-e2e.md` when it exists.) Run `B set $ID stage=build`, then go to **Check gate**.
   - `verdict` is `CHANGES` and `round >= limit`: go to **Approve**.
