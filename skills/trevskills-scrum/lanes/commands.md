# Commands

For `approve` and `rework`, load the job from `$F/board.json`: `WT` is its `worktree`, `BASE` is its `base`, and `DEFAULT` is `BASE` with the `origin/` prefix removed. `N` is its `round`.

- **`/trevskills-scrum`** (no args): first run **Cloud lane** **Sync** when a job is in stage `cloud`. Then print each job's `id stage round reason pr` from `$F/board.json`, and the dashboard command.
- **`/trevskills-scrum next`**: first run `B watchdog`. It flags every job stuck 30+ minutes in `spec`, `build`, `check`, `review` or `approve` with no live session, leaving each stuck job in its stage with board `stalled` true and reason `stalled: ...` (never `needs-human`), and prints `{"flagged"}`; a stuck `spec` job with no `feature.md` (a claim whose session died first) is aborted instead and its backlog line reopened in place, never flagged; for each flagged id that has a `parent`, run **BigBoy lane** step 6 with `ID=<that id>`. Then run `B next`. It claims the first `- [ ]` line in `$F/backlog.md` that waits on nothing, under the board lock, creates the job, and prints `{"id", "feature"}`. If `id` is null, say the backlog is empty (or every open item waits on a prerequisite) and stop. Otherwise run **New job** from step 1b with `ID=<id>` and that feature text (step 2 records your terminal).
- Backlog lines look like `- [ ] [5] Text {#k3f9} {needs #a1b2} <!-- estimate reason -->`; the `[5]` is Fibonacci difficulty points. The optional ` {#k3f9}` is the item's id (4 chars `[a-z0-9]`) and ` {needs #a1b2 …}` lists the ids of items it waits on; both sit after the text and before any ` → <job>`, and the item's text excludes them. A prerequisite still blocks while its line is open, or while the job that claimed it is not `done` or `aborted`; an unknown id never blocks. `next` and `runall-start` skip an item that waits: `next` takes the first open item that waits on nothing (`next --index` on a waiting item fails with `waits on #<id>`), and `runall-start` leaves an item open when it waits on a job claimed outside the run. The optional ` {setup: <step>; <step>}` marker, after ` {needs …}` and before any ` → <job>`, is a Human setup checklist that only Trevor can do (added with `B backlog-add --setup`): `next` skips the item (`next --index` on it fails with `waits on Human setup`), `runall-start` leaves it open, and an item that needs it stays open too. The dashboard Backlog dialog's Setup done button on that item removes the marker (backlog op `setup-done`), and the item is then claimable like any other. Only ever change `backlog.md` through `B` (`next`, `backlog-add`, `triage-apply`), never by hand-editing it. Checks only a human can do live in `manual-checks.md` instead (`- [ ] Text`, added with `B manual-add`); no job ever runs them.
- **`/trevskills-scrum <feature text>`**: run **New job**.
- **`/trevskills-scrum now <feature text>`**: the same as the bare `/trevskills-scrum <feature text>` (run **New job**).
- **`/trevskills-scrum next <feature text>`**: run the **Dupe check** (New job step 3c, with `$F/jobs/none` as the job folder), then `B backlog-add --top -- '<text>'`: the item goes first with `{p:5}`, so the next claim takes it. It starts no job and does not rank. Bare `/trevskills-scrum next` with no text stays as above: watchdog, then claim.
- **`/trevskills-scrum later <feature text>`**: run the **Dupe check** and **Rank** (New job step 3c, with `$F/jobs/none` as the job folder), then `B backlog-add [--priority N] -- '<text>'`. It starts no job.
- **`/trevskills-scrum askme [1-3] <feature text>`**: run **New job** with the **Askme** step (1c) at that level. With no level, or a level that is not 1, 2 or 3, use level 2 and treat the whole rest as the feature text.
- **`/trevskills-scrum bigboy <feature text>`**: run **New job** steps 1-2, then `B set $ID lane=bigboy` and go straight to the **BigBoy lane**. No spec writer runs for the parent.
- **`/trevskills-scrum lilguy <feature text>`**: run the **Lilguy lane**. No agent is spawned.
- **`/trevskills-scrum roadmap <brief>`**: draft `$F/roadmap.md` from the brief and, on Trevor's yes, start P1 S1 (**Roadmap lane**).
- **`/trevskills-scrum roadmap`** (no brief): print the roadmap status block (**Roadmap lane**). It starts nothing.
- **`/trevskills-scrum start <id>`**: the dashboard's Run now button already claimed a backlog item as job `<id>` and wrote its `feature.md`. Load the job and run **New job** from step 2. For a BigBoy child (the job has a `parent`; started as `/trevskills-scrum start <child>` by **BigBoy lane** step 3 or by the dashboard's Setup done), run **BigBoy lane** step 4 (Spec refresh) after step 2: it skips step 3 when `spec.md` exists and no refresh is needed.
- **`/trevskills-scrum start <id> askme <1-3>`**: the same, but the dashboard's Run now had Askme set, so it opened this session in a new Terminal window. Load the job and run **New job** from step 1c (Askme) at that level; a missing or bad level means level 2.
- **`/trevskills-scrum approve <id>`**: the job must be `needs-human`. **refuse** (and suggest `/trevskills-scrum rework <id> "<feedback>"` instead) if the job has no `worktree`, has no commits beyond `BASE` (`git -C "$WT" log --oneline "$BASE"..HEAD` is empty), or its reason starts `blocked`, `spec writer`, `obsolete` or `stalled`; there is nothing approved to merge (for `stalled`, suggest `/trevskills-scrum resume <id>` instead). Also run Merge step 1's **main checkout guard**, self-heal included; when it ends in its `B ask` (`Uncommitted change in <repo name>: ...` or `<repo name> main checkout is on <branch>, ...`), stop there and don't write `human-approval.md`. Once it passes, continue. When the prompt says `Trevor confirms /trevskills-migrate has already been run` (sent by the dashboard when he ticks that box), write `git -C "$WT" rev-parse HEAD:prisma` to `$F/jobs/<id>/migrated.md` so **Merge**'s schema guard skips **Migrate**. On reason `migrate needs your OK`, copy `prod-approval-pending.md` to `prod-approval.md` in `$F/jobs/<id>/`. On a reason starting `retry:` (a woken `wait-on --then` job), sync the branch so **Merge**'s schema guard sees the blocker's merged migration: `git -C "$WT" fetch origin`, then `git -C "$WT" merge "origin/$DEFAULT" --no-edit`; on a conflict, run `git -C "$WT" merge --abort` and carry on unmerged, with no `B ask` and no stop (the **Conflicts** step in **Merge** handles it). Then **record your terminal** with `ID=<id>`, write `$F/jobs/<id>/human-approval.md` containing `Approved by Trevor <ISO date>` and run **Merge**.
- **`/trevskills-scrum rework <id> <feedback>`**: append `## <ISO date>\n<feedback>` to `$F/jobs/<id>/rework.md`. **Off-track BigBoy parent** (the job has `children` and its reason starts `bigboy off track`): Trevor's note is his decision on the plan, so no builder runs. **Record your terminal** with `ID=<id>`, run `B set --unpause <id> stage=running reason=`, then `B chain-lock <id> <id>` (same tries and stop as **BigBoy lane** step 5). Spawn `scrum-tracker` with the **BigBoy lane** step 5 prompt (`P=<id>`) plus the line `Trevor's decision is in PARENT_DIR/rework.md: read it first and follow it.` Handle its `track-N.md` exactly as step 5 sub-step 1 does (ADJUST re-runs step 2 for the rewritten children; OFF TRACK sets the off-track reason again, unlocks and stops), then run step 5 sub-steps 2-3 (with `B chain-unlock <id> <id>`) and stop. Every other job: run `B set --unpause <id> stage=build reason= limit=<round+2>`, then **record your terminal** with `ID=<id>`. If the worktree is gone, recreate it from the branch with `git worktree add "$REPO/.claude/worktrees/scrum-<id>" scrum/<id>`. If the job's `lane` is `debug` and `$F/jobs/<id>/assessment.md` is missing or its first line is not `ASSESSMENT: READY`, no builder ever ran, so re-diagnose instead: move `assessment.md` (if present) to `assessment-prev.md`, run **Debug lane** from step 1 with the debugger prompt extended by `Read JOB_DIR/rework.md first.` and the re-spawn line, and continue as Debug lane does. Otherwise resume the builder (see **Resuming the builder**) pointing it at `rework.md`, then continue at **Check gate**.
- **`/trevskills-scrum discuss <id> [<note>]`**: an interactive talk-through before anything goes back to the builder. The dashboard's Discuss first button opens it in a new terminal, with whatever Trevor typed as the note. The job must be `needs-human`. **Record your terminal** with `ID=<id>`. Read only the board `reason`, the first lines and `## Rulings` of `decision.md`, `rework.md`, and `migrate-stop.md` if it exists. Then tell Trevor in plain words:
  1. What is stopping the job.
  2. Whether a rework can clear it. A `Hard stop:` never clears through rework: the builder can fix code, but the approver stops again on the same hard stop. Only `approve` clears it (for `migrate stopped`, approve runs `/trevskills-migrate` again through **Merge**).
  3. What his note would actually do: change code (rework), give the go-ahead (approve), or neither.

  Discuss until you agree. Spawn nothing, edit nothing and run no command until Trevor picks one. Then carry it out in this session exactly as that command: `approve <id>`, or `rework <id> "<the agreed feedback, written so the builder can act on it>"`. If he picks neither, stop.
- **`/trevskills-scrum resume <id>`**: the dashboard's Resume button starts it headless for a job `B watchdog` flagged or one stopped for another resumable reason, and its Play button for a job Trevor paused. The job must have board `paused` true, or be `needs-human` with a reason starting with one of `board.py`'s `RESUMABLE` prefixes: `stalled in <stage>`, `bigboy off track`, `bigboy review: main not updated`, `bigboy blocked` or `Base branch `, or with an open question whose board `options` hold `resume <id>` or the prompt's `shell:` command (**Answered question** below), or be a `running` BigBoy parent with reason `waiting: main fast-forward` (serve.py starts it once main fast-forwards), or have board `stalled` true in its stage; or sit in a WATCHED stage held by `limitResetAt` (not paused): accept it and re-enter that stage like `stalled`, whose `B set --unpause` also drops `limitResetAt`; otherwise **refuse** and stop. **Record your terminal** with `ID=<id>` right after the first `B set` below (a paused job refuses every write before `B set --unpause`), or first when the branch has none. Then re-enter by reason. **`bigboy off track`**: run `B set <id> stage=running reason=`, then **BigBoy lane** step 5 sub-steps 2-3 with `P=<id>` (`B chain-lock <id> <id>`, `B ready`, `B chain-unlock <id> <id>`, then **start** each ready child, or step 7 when `all_merged`), skipping the tracker. **`bigboy review: main not updated`** or **`waiting: main fast-forward`**: re-check main: `git -C "$REPO" fetch` (`DEFAULT` from the job's `base`), then `git -C "$REPO" merge-base --is-ancestor HEAD origin/$DEFAULT`, plus **Merge** step 7's **Fast-forward main**; on `uncommitted changes` alone, self-heal as **BigBoy lane** step 7 does, then re-check. If any still fails, run `B set <id> reason='waiting: main fast-forward'` and stop for `waiting: main fast-forward`, else run `B ask` again with the same question, options, `--title` and --recommend and stop. Otherwise run **BigBoy lane** step 7 with `P=<id>`, without its `main not updated` check. **`bigboy blocked`**: read the parent's children from the board and run `B abort <c> --reason 'skipped: depends on aborted <ids>'` for only the `waiting` children that depend (directly or through another `waiting` child) on an aborted sibling (`<ids>` are the aborted children it depends on). If none do, run `B ask <id> '<its reason>' --a "Carry on=resume <id>" --b "Remove this job=abort <id> --cascade" --title BIGBOY_BLOCKED --recommend <key> '<why>'` (the reason rewritten to the **Issue** bar in `lanes/stops.md` with its prefix kept, then quoted under **Untrusted reason text**) and stop. Otherwise run `B set <id> stage=running reason=`, then **BigBoy lane** step 5 sub-steps 2-3 with `P=<id>` (step 7 when `all_merged`). **`Base branch `**: run `B set <id> stage=spec reason=`, then **New job** from step 2. Step 2 re-reads project.md and stops again with the same reason if the line is still bad. **`stalled`** (board `stalled` true, or a legacy `stalled in <stage>` reason): load it like `approve` (`WT`, `BASE`, `DEFAULT`, `N`), run `B set --unpause <id> stage=<the job's stage> reason=` (first: a paused job refuses every other write; for a legacy reason, the `<stage>` it names), and re-enter at that stage (a lilguy job with a worktree: **Lilguy lane**): `spec`: **New job** from step 3; `plan`: delete `$F/jobs/<id>/plan.md` if present and run **BigBoy lane** from step 1; `merging`: **Merge** from step 1; `build`: resume the builder (see **Resuming the builder**) with `Your session was interrupted: finish the work, commit, update build.md.`, then **Check gate**; `check`: **Check gate** from step 2 (step 1 already set the round); `review`: run `B sync <id>`, spawn (as **Review** step 3) only the reviewers named in its `missing` (the skip and carried-forward files of **Review** step 2 are written before any spawn, so `missing` never names them; a resumed session can't tell how the round started, so it writes no new carried-forward file and spawns them on the full diff), then continue at **Review** step 4 (a `lane=fast` job spawns only `scrum-review-code` and the **Fast lane** step 2 UI reviewer, each when its review file is missing, and continues as **Fast lane** step 2 does after its spawn); `approve`: **Approve** step 1. **`Weekly digest `**: run `B set <id> stage=spec reason=`, then **New job** from step 2. Step 3 finds the pre-written `spec.md` and skips the spec writer. **Skip it** is an `abort` option, so it never reaches resume. **Answered question** (any other reason): Trevor picked a `resume` or `shell:` option. A `Trevor picked "<label>": run <cmd>, then continue` note's `shell: <cmd>` must be in the job's board `options` (else **refuse**); run it from `$REPO`, and if it fails, `B ask` again with the same question, options, `--title` and --recommend and stop. Then find the step whose `B ask` wrote the question (its text up to the first `<placeholder>`), load the job like `approve`, run `B set --unpause <id> stage=<that step's stage> reason=` and re-run that step. From there the job runs to the end as a `start` session would, including **BigBoy lane** chaining for a child.
- **`/trevskills-scrum digest`**: run **Digest**. The dashboard's Digest now button starts it headless.
- **`/trevskills-scrum weekly-digest <NNN>`**: run **Digest** `## Weekly` with that `<NNN>`. serve.py's watchdog starts it headless.
- **`/trevskills-scrum cloud [N]`**, **`/trevskills-scrum cloud-sync`**, **`/trevskills-scrum cloud-home <id>`** and **`/trevskills-scrum cloud-job <id> <feature text>`**: run the **Cloud lane**.
- **`/trevskills-scrum run-all`**: run **Run all**: triage, then schedule every open item in parallel where files don't overlap. The dashboard's Run all button opens it in a new Terminal window when Trevor picks Askme Off.
- **`/trevskills-scrum run-all askme <1-3>`**: the same, with the **Askme** step of **Run all** at that level, so this session asks Trevor about every item before any child starts. The dashboard's Run all button opens it when Trevor picks level 1, 2 or 3. A missing or bad level means level 2.
