# Stops

Every `B ask` reads as Issue / Options / Recommended. The question is the Issue; never write the words Issue or Options into it.

- **Issue:** the machine prefix, first and unchanged (`Hard stop: schema — `, `blocked: `, `debug: `, ...), then plain words that say what happened and why it needs Trevor, the whole question at most 40 words with the rest in stop.md; the options plus the `--recommend` `<why>` say what each button does. The dashboard hides the prefix, so the text after it must read on its own. The text after the prefix is at most 40 words; anything longer goes in `stop.md`. The question and the `<why>` never use a file path or a rule number, even with an explanation: name the file by what it holds (`the email skill's customer notes`, not its path).
They never use a file pointer (`see ci.md`) or an internal term (`human-only`, `lane`, `hard stop`, `rework`, `BigBoy`) without saying what it means. Name `stop.md`, `ci.md`, `check.md` or `decision.md` by bare name only, never with its folder (`round-1/check.md`). The question is at most 40 words; anything longer goes in `stop.md`. Example: `This change adds a database column, which agents aren't allowed to apply on their own. Reviews and tests passed. Apply it and merge?` Every number in a question names what it measures and its limit: `1-minute CPU load average 14 on an 8-core Mac (limit 8)`, never load above 8.
- **Rewrite:** whoever composes the ask rewrites any templated or passed-through text (a lane template, decision.md line 2, an unblocker `## For Trevor` line) to meet this bar before calling `B ask`, keeping its prefix.
- **Detail:** the question is at most 40 words; file lists, logs, the full cause and anything long go in `jobs/<id>/stop.md` (`$F/jobs/$ID/stop.md`), written before the ask; the question says in words what the detail holds and where it is shown (e.g. `the full file list is in the stop.md tab of this job`).
- **Options:** the A/B/C trio where it fits: A carry on or merge (`Carry on`, `Try again`, `Merge anyway`), B send back with a note (`Send back with a note`), C remove this job (`Remove this job=abort <id> --cascade`). A `--requeue` option reads `Put back on the backlog`. Labels are plain words, never a bare `Abort`.
- **Title:** `--title <KEY>` right before `--recommend`, one key from this list, exact and in capitals. The dashboard shows it, with `_` as a space, as the heading of the stop. `board.py ask` refuses any other value. The keys: `UNCOMMITTED_CHANGES`: the main checkout or the job's worktree has files nobody committed; `WRONG_BRANCH`: the main checkout is on another branch, or the profile's Base branch line is malformed or missing on origin; `MERGE_CONFLICT`: the branch still conflicts with the default branch after two tries; `CHECKS_FAILING`: tests or CI still fail after the allowed fix attempts (debug fixes included); `MERGE_BLOCKED`: GitHub will not take the merge (the PR was closed, the merge or done step was refused, or the GitHub CLI is missing or signed out); `PROD_CHECK_FAILED`: the change merged, but the production deploy, a production data run or the production check failed; `DATABASE_CHANGE`: the job changes the database structure, and the migrate needs an OK or it stopped; `PROD_APPROVAL`: the database update needs Trevor's OK before it runs on production; `ROUND_LIMIT`: the approver asked for a second round of fixes, and a job only gets one; `BUILDER_BLOCKED`: the builder, debugger or approver could not go on (`blocked:`, `debug: blocked`, `Hard stop: blocked`); `REVIEW_ESCALATED`: the approver escalated for another reason (`Hard stop: render`, any other decision line, or output that could not be read); `BIGBOY_OFF_TRACK`: the tracker says the remaining tickets no longer reach the goal; `BIGBOY_BLOCKED`: a multi-ticket job cannot start its next ticket, because the chain lock is held or its children are blocked; `DEPENDENCY`: a job this one waited on finished, was aborted or was removed; `MD_CONTRADICTION`: a knowledge-save job found a fact that contradicts the target .md or the code; `DIGEST`: a weekly digest proposal, a digest edit that failed to apply, or a pipeline-health finding; `TWO_SESSIONS`: two sessions were working the same job at once and the watchdog could not tell which one owns it; `AGENT_MISSING`: a scrum agent could not be loaded (Agent type not found), so the job stopped instead of running a stand-in agent; `VIDEO_REVIEW`: a video job needs Trevor to approve its storyboard or a cut, or to send notes. `EDIT_APPROVE`: an edit is ready; the card is green with a View button, and Trevor approves it or sends notes. `CONTENT_QUESTIONS`: an ops content job needs Trevor's answers before it can write the draft; `CONTENT_DRAFT`: an ops content job has a draft ready for Trevor to approve or send notes on; `DATA_RUN`: an ops data job needs Trevor's OK before it runs on production data.
- **Recommended:** `--recommend <key> '<why>'` after the last option. `<key>` is the option you advise, picked by your own judgement; `<why>` is one short reason with every `'` removed. It is its own reason, never a `<why>` the question or an option already uses.
- Machine load (CPU load average, RAM, swap) is never a reason to `B ask`: a heavy run waits in a lock, or runs anyway. A Test, Build or E2E run that failed or timed out while the machine was overloaded (and no assertion points at the diff) is not a stop: ask `waiting on a quiet machine: <what failed>` with `--title CHECKS_FAILING`, and board.py holds the job until load drops. Exception: a run `B e2e-budget` calls `over_budget` true with `failed` 0 and `passed` at least 1 is the over-budget case of `lanes/newjob.md` (record its line, no ask), whatever the load; only a run with no passed test, or a failed test with no assertion pointing at the diff, can be this ask.
- A re-ask passes the same question, options, `--title` and --recommend, because an ask without `--recommend` drops the advice and an ask without `--title` is refused.
- **Wrong project:** a session that finds the job edits the scrum tool itself (board.py, serve.py, dashboard.html, or the skills and agents in trevskills-scrum) from another project never calls `B ask`. It moves the item to the trevskills-scrum backlog automatically, with no question, because that ask sat unanswered 9 of 10 times (digest 114).
- **Never only resume or abort:** an ask whose options are all `resume` or `abort` is refused. Add a `followup <id> "<fix>"` option (as **Merge** step 5 does), and where the stop only waits on another job (a `Hard stop: schema` ask that waits on a job merging) run `B wait-on <id> <blocker>` instead of asking.
