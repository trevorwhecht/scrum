# Cloud lane

Runs backlog jobs in Claude Code cloud sessions (claude.ai/code), paid by Trevor's cloud-session credit instead of his weekly plan. The cloud environment's setup script is `cloud/setup.sh` from the scrum repo, so the session loads this same skill and agents. Only the differences are listed; every other step runs as written.

1. **Dispatch** (`/trevskills-scrum cloud [N]`, N defaults to 4; from the main checkout; Setup and Prerequisites apply). First run **Sync** (step 3). Then refuse with a plain message and start nothing when:
   - `$F/project.md` has a `Base branch:` line: `Cloud lane does not support Base branch yet. Fix: run these jobs locally.`
   - `git -C "$REPO" status --porcelain -- . ':(exclude)scrum'` prints anything, `git -C "$REPO" symbolic-ref -q --short HEAD` is not `$DEFAULT` (found as in **New job** step 2), or after `git fetch origin` `git -C "$REPO" rev-list "origin/$DEFAULT..HEAD"` prints anything: `<repo name> must be clean, on <default> and pushed. Fix: commit and push or discard, then run cloud again.`
   - **Credit check (before every batch).** The credit balance has no API, so the last value is cached in `~/.claude/trevskills-scrum/cloud-credit.json`, shaped exactly `{"usd": <number>, "checked_at": "<UTC ISO 8601, e.g. 2026-10-18T09:30:00Z>", "dispatched": <int>}`. First read that file: when it exists, parses, has all three keys with those types, `checked_at` is under 24 h old and `usd` is above $25 plus $5 per job dispatched since (`usd > 25 + 5 * dispatched`), the check passes: no Chrome read and no AskUserQuestion. When the file is missing or unreadable (no file, bad JSON, a key absent or of the wrong type), `checked_at` is 24 h old or more, or `usd` is not above that floor, run the full check. When the Claude in Chrome tools are available (`mcp__claude-in-chrome__*`; read the chrome-browser skill first), open https://claude.ai/settings/usage in a new tab and read `Cloud session credits ... $X of $250 left`. If X is under $25: `Cloud credit is $X, under $25. Fix: top up, then run cloud again.` If the tools are missing or X can't be read, ask Trevor once with AskUserQuestion how many dollars of cloud credit are left; a number of $25 or more is the confirmation and becomes X; any other answer (no, blank, not a number, under $25) refuses with `Cloud credit unreadable and unconfirmed.` Whenever the full check gets a value (read from Chrome, even under $25, or confirmed by Trevor), run `mkdir -p ~/.claude/trevskills-scrum` and overwrite the file with `{"usd": X, "checked_at": "<now, UTC>", "dispatched": 0}`.

   Then, after the credit check, run `B cloud-claim "$N"` once. It claims up to N open backlog items under the board lock, in backlog order, and prints `{"claimed": [{"id", "feature"}, ...]}`. It skips (leaves open) an item that waits on a prerequisite or on Human setup, has no pre-written spec with `## Likely files` paths, or shares a Likely file with an item claimed in this call or with a job in stage `cloud` or `build`, or in stage `spec` claimed by an earlier `B cloud-claim` (one of those with no readable Likely files blocks every item). When `claimed` is empty, start nothing and say so; skipped items stay open for a later run. For each `id` in `claimed`, with `ID=<id>` and its `feature` text, run the rest of this step: write the feature text to `$F/jobs/$ID/feature.md` (**New job** step 1b). The cloud session sees neither `jobs/` nor `digests/` (both stay on this Mac), so make `feature.md` self-contained before the session reads it:
   - **Pre-written spec.** When `$F/jobs/$ID/spec.md` exists (`B cloud-claim` moved it there from the backlog), append it to `feature.md` under a `## Pre-written spec` heading.
   - **Digest proposals.** When the feature text names a local `.../digests/<NNN>/proposals.json` path (older digest items), read that digest's proposals from `$F/digests/<NNN>/proposals.json` and, for each proposal id the text names (`digest <NNN> <PID>`), append a `## Digest proposal <NNN> <PID>` section with the target relative to the repo, the why, and the old and new text, each in a backtick fence longer than any backtick run inside it. End the section with: `This section replaces the local proposals.json path: do not open proposals.json or run --digest-skill-check. The item is obsolete when the old text is not found exactly once in the target (edit) or the target already exists (skill, empty old).`
   - **Missing proposal.** When a proposal the text names is not in that file (or the file is missing), start no session for this job and run `B abort $ID --requeue --reason 'requeue: digest proposal <NNN> <PID> not found in proposals.json'`.

   Then start the session (macOS `script` gives `claude --cloud` the TTY it needs; the feature text stays inside a variable so the shell expands nothing in it; the environment goes in through `--settings`, because the environment flag takes only self-hosted `ccpool_` ids, and nothing may sit between `--cloud` and its prompt, or that flag swallows it):
   ```bash
   CE=$(sed -n 's/^- Cloud environment: *//p' "$F/project.md" | head -1 | sed 's/[[:space:]]*$//'); E=()
   printf '%s' "$CE" | grep -qE '^[A-Za-z0-9_-]+$' && E=(--settings "{\"remote\":{\"defaultEnvironmentId\":\"$CE\"}}")
   FEAT=$(cat "$F/jobs/$ID/feature.md")
   OUT=$(script -q /dev/null claude "${E[@]}" --cloud "First run: bash ~/scrum/cloud/setup.sh (the environment caches an old copy of the skill). Then check that the refresh took: git -C ~/scrum rev-parse HEAD must print the same hash as git -C ~/scrum ls-remote origin refs/heads/main, and grep -q scrum-artifacts/ ~/.claude/skills/trevskills-scrum/lanes/cloud.md must succeed. Then read ~/.claude/skills/trevskills-scrum/SKILL.md with the Read tool and follow that file, not any skill text loaded at session start. When either check fails, stop before New job with needs-human reason: this cloud session is running an old copy of the scrum instructions; rerunning cloud setup refreshes it. Report it to GitHub as that file's Cloud job Needs-human step does (a [scrum $ID] PR labelled scrum:needs-human, with the reason as the first comment line). Otherwise run: /trevskills-scrum cloud-job $ID $FEAT" < /dev/null 2>&1)
   URL=$(printf '%s' "$OUT" | grep -oE 'https://claude\.ai/code/session_[A-Za-z0-9_-]+' | head -1)
   ```
   With a `URL`, run `B set $ID stage=cloud cloud=$URL`, then add 1 to `dispatched` in `~/.claude/trevskills-scrum/cloud-credit.json` (rewrite the file, other keys unchanged; skip when the file is missing or unreadable). Without one (the session did not start, so `dispatched` stays as it is), run `B abort $ID --requeue --reason 'requeue: claude --cloud did not start: <last line of OUT>'` (`<last line of OUT>` quoted under the **Untrusted reason text** rule). Stage `cloud` is never flagged by `B watchdog`. The final report lists each id with its session URL.
2. **Cloud job** (`/trevskills-scrum cloud-job <id> <feature text>`, inside the cloud session). The job runs **New job** end to end (spec → build → Check gate → Review → Approve → Merge) with these deltas:
   - **Setup:** the cloned repo is the main checkout, and its `scrum/` is a throwaway board: first-run setup as usual, minus step 5. On a shop run (`SCRUM_SHOP` set), dispatch has already written `$F/project.md` from the main Mac's: keep it, and still run first-run setup steps 1–3, which skip what is already there. Prerequisites check `gh api user` instead of `gh auth status` (cloud `gh` is signed in through a proxy that `gh auth status` rejects). Skip Roadmap resume and **Record your terminal**: no dashboard, tty or terminal recording here.
     When this session's skill copy lacks the **Artifacts** step below, or `git -C ~/scrum rev-parse HEAD` differs from the hash `git -C ~/scrum ls-remote origin refs/heads/main` prints, or `grep -q scrum-artifacts/ ~/.claude/skills/trevskills-scrum/lanes/cloud.md` fails (the same two checks the launch prompt runs), the launch prompt's setup.sh refresh did not take: it stops before New job with needs-human reason `this cloud session is running an old copy of the scrum instructions; rerunning cloud setup refreshes it.` and reports to GitHub as **Needs-human** does. On a shop run (`SCRUM_SHOP` set), the skill copy is `~/code/scrum`, which md_sync pulled just before dispatch, so both git checks read `~/code/scrum` instead of `~/scrum`.
   - **Job:** New job step 1 is `B new "<title>" --id <id>`, so the job keeps the id it was given; then step 1b, then step 2 on. A spec that says `Lane: bigboy` counts as `standard`, as for a BigBoy child.
     On a shop run (`SCRUM_SHOP` set), step 3's **Lilguy route** runs `B lilguy-fit $ID` right after New job step 2, before any spec.md is read or written and before the pre-written spec's `Lane:` line is read, so every shop job leaves `jobs/$ID/lilguy-fit.json`; on `fit: true` the job runs the **Lilguy lane**, its PR body saying `Scrum lane: lilguy`.
   - **Reviewers always run:** a `fast` or `standard` job runs every New job step as written, spawning its builder and reviewers and running the Check gate, even on a one-line diff or a repo with no tests; only the Lilguy lane (after `B lilguy-fit $ID` prints `fit: true`) makes the change itself and skips them. Merge runs its step 1 guards, then its step 2 `B set $ID stage=merging`, which refuses a `fast` or `standard` job until a `round-N/review-code.md`, decision.md or human-approval.md exists.
   - **Routing** is always cloud: never call route.py; every routed step spawns with the Agent tool as written.
   - **GitHub:** cloud blocks GitHub GraphQL, so each `gh pr` call in **Merge** becomes its REST twin, with `R='repos/{owner}/{repo}'` (`gh` fills it in from origin). These are the same sanctioned PR create and squash-merge.
     - step 3 lookup: `gh api "$R/pulls?head={owner}:scrum/$ID&state=all" --jq '.[0] | {number, html_url, state, merged_at}'` (`merged_at` set is MERGED);
     - step 3 create: the head is `scrum/$ID` and the title starts `[scrum $ID] `, where `$ID` is the full job id, never its number alone, another branch or the bare Merge summary title (that is how **Sync** finds it): `gh api "$R/pulls" -f title="[scrum $ID] <title>" -f head="scrum/$ID" -f base="$DEFAULT" -F body=@"$BODY" --jq .html_url`. Every `[scrum <id>]` PR body this session creates has its own line `Scrum lane: <fast|standard|debug|lilguy>`, the lane the job actually ran: a spec that says `Lane: bigboy`, or a job stopped before its spec picked a lane, is written `Scrum lane: standard`;
     - step 4 checks, in the background: `SHA=$(git -C "$WT" rev-parse HEAD)`, then every 15 s `gh api "$R/commits/$SHA/check-runs" --jq '[.check_runs[] | .conclusion // "pending"] | unique | join(" ")'` until it has no `pending`; still empty after 90 s is "no CI ran"; anything but `success`, `skipped` and `neutral` is a failure, and `ci.md` gets each failing run's name, conclusion, `html_url` and `output.summary`;
     - step 5: `gh api "$R/pulls/<number>" --jq .mergeable`, where `null` is `UNKNOWN` and `false` is `CONFLICTING`; the **Conflicts** steps then run unchanged, which is also how parallel cloud jobs settle conflicts;
     - step 6: `gh api -X PUT "$R/pulls/<number>/merge" -f merge_method=squash -f commit_title="<title> (#<number>)" -F commit_message=@"$BODY"`.
   - **Merge** auto-merges under exactly the local rules: every stop the local rules keep (blocked, and schema, which never migrates here: see the next bullet) still stops. Skip step 1's main checkout guard. Step 7 is only `B set $ID stage=done reason=`: no worktree removal, fast-forward, restart, verify, chaining or Digest (local **Sync** fast-forwards Trevor's checkout). The Prod check does not run in the session either: the **Cloud-home tail** runs it. A `standard` job still writes `decision.md` (its approver is spawned as in **Approve**, with its `## Prod runs`, `Deploy` and `Prod check` lines), so the tail can read them.
   - **Never migrate in cloud:** never run `/trevskills-migrate`, `prisma migrate` or `prisma db push`; `approve` and its migrate step only ever run locally. A `Hard stop: schema` (from the approver or the Merge schema guard) is reported as **Needs-human** below, so its comment's first line starts `Hard stop: schema`, and **Sync** migrates it locally.
   - **Needs-human:** every time this job would run `B ask` (or abort itself as obsolete, with its `obsolete: ...` reason, or with a `requeue: ...` auto-abort or `looks already fixed: ...` close from **Auto-abort instead of needs-human**), it also reports to GitHub, then stops: push `scrum/$ID` (with no commits beyond `$BASE`, push `$(git commit-tree "$BASE^{tree}" -p "$BASE" -m "[scrum $ID] needs-human")` to `refs/heads/scrum/$ID` so a PR can exist), open the PR as above (its body with the `Scrum lane:` line) or keep the open one, add the label with `gh api "$R/issues/<number>/labels" -f "labels[]=scrum:needs-human"`, and post a comment whose first line is the question (written to the **Issue** bar in `lanes/stops.md`) and whose second line is `<!-- scrum needs-human -->`, with `gh api "$R/issues/<number>/comments" -F body=@<file holding it>`.
   - **Artifacts:** every time the job ends (merged, needs-human or obsolete abort), as its last action before it stops (after Merge step 7's `B set`, or after the **Needs-human** PR, label and comment), push the job folder to `scrum-artifacts/<id>` without touching the checkout or its index, so local **Sync** can bring it home. A shop run (`SCRUM_SHOP` set) pushes it too: the shop's `scrum/jobs/` never reaches this Mac any other way. Run the block as one Bash call with `<id>` replaced by the job id. It sets `ID`, `REPO` and `$F` itself from any cwd in the main checkout, its `scrum/` or a job worktree, and runs the same in bash and in zsh (the shop's Bash), so it braces every variable written right before a `:`:
     ```bash
     ID=<id>; S='push failed'; I=$(mktemp -u); R="refs/heads/scrum-artifacts/$ID"
     REPO=$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)"); F="$REPO/scrum"
     if cd "$F" && L=$(python3 "$HOME/.claude/skills/trevskills-scrum/board.py" --dir "$F" artifacts "$ID"); then
       printf '%s\n' "$L" | tr '\n' '\0' | GIT_INDEX_FILE="$I" xargs -0 git add -f --
       if [ -z "$(GIT_INDEX_FILE="$I" git ls-files)" ]; then S='nothing staged'; else
         T=$(GIT_INDEX_FILE="$I" git write-tree) && C=$(git commit-tree "$T" -m "[scrum $ID] artifacts") &&
           for N in 1 2 3; do
             git push origin "${C}:$R"
             [ "$(git ls-remote origin "$R" | cut -f1)" = "$C" ] && S=pushed && break
             [ "$N" = 3 ] || sleep 5
           done
       fi
     fi
     rm -f "$I"; cd "$REPO"; echo "artifacts: $S"
     ```
     `board.py artifacts` prints only the files that are safe to push and names the rest in `skipped-secrets.txt`; when it fails (no job folder), nothing is pushed. The push is tried 3 times, 5 s apart, and counts only once `git ls-remote` shows the new commit. The final report quotes the block's last line, `artifacts: pushed`, `artifacts: push failed` or `artifacts: nothing staged` (`git add` staged no file, so no empty-tree branch is pushed). The branch is never merged and never has a PR. The cloud session never deletes or force-pushes an artifacts branch: only this Mac's **Sync** deletes it, in **Artifacts home**, after the folder came home. A failed push is reported in the final report but does not change the job's outcome.
3. **Sync** (`/trevskills-scrum cloud-sync`; also the start of `cloud` and of bare `/trevskills-scrum`). Run `B cloud-sync`, never `gh pr list` or `gh pr view`: it finds each `cloud` job's newest `[scrum $ID]` PR whose head is this repo's own scrum/$ID branch (a fork's PR, or one from another branch, is ignored; a short `scrum/<number>` head or `[scrum <number>]` tag also matches, a tag naming another job is ignored, and an untagged title is matched by its head) with one GitHub REST pulls call and makes the board update itself, with no LLM. It prints `{"moved": [{"id", "state", "pr", "reason", "worktree", "artifacts"}], "arrived": [ids], "error"}`. A job moved before its `scrum-artifacts/$ID` branch exists gets an internal `artifactsPending` mark; each later run re-checks it, lists the id in `arrived` once the branch exists, and drops a mark whose branch is still missing after 24 h. When it exits 1 (`gh` not signed in, offline, any `gh` failure), nothing changed: report its `error` and skip the rest of Sync. serve.py also runs it every 10 minutes while a job is in stage `cloud` or carries `artifactsPending`, and starts `/trevskills-scrum cloud-home <id>` headless for each id in `arrived` and for each job it moved with `artifacts` true or a reason starting `Hard stop: schema`. For every job it moves (merged, needs-human or aborted), `B cloud-sync` also writes `lane=<lane>` from the PR body's `Scrum lane:` line; with no valid line it writes no lane. Per job, `B cloud-sync` does exactly this:
   - No PR, or an open PR without the `scrum:needs-human` label: still running; leave it.
   - PR `MERGED`: `B set $ID stage=done pr=<url> reason=` (the done guard re-checks the PR).
   - PR `OPEN` with label `scrum:needs-human`: the reason is the first line of the newest `<!-- scrum needs-human -->` comment posted by the PR's author (comments by anyone else are ignored; cut to 300 characters; with no such author comment, `cloud job needs a human; no reason comment on <url>. Fix: read the PR.`). When that line starts `requeue:`, `obsolete:` or `looks already fixed:`, the cloud job aborted itself: instead of needs-human it records `pr=<url>`; an `obsolete: needs Trevor` reason first runs `B manual-add '<line without obsolete: > (from $ID)'` (a failure is printed, and the abort still runs); `requeue:` becomes `B abort $ID --requeue --reason '<line>'` (without `--requeue` for a job with a `parent`), and `obsolete:` or `looks already fixed:` becomes `B abort $ID --reason '<line>'`. Then it closes the PR as `gh pr close <number>` would, through a REST `PATCH` of its `state`; a failed close is printed, not retried. Otherwise it runs `git fetch origin` and, as `rework` does, `git worktree add "$REPO/.claude/worktrees/scrum-$ID" "scrum/$ID"`, then moves the job to needs-human with `pr=<url> base=origin/<baseRefName> worktree=$REPO/.claude/worktrees/scrum-$ID reason=<reason>` (board.py's own write, since `B set` refuses that stage; leaving out `worktree=` when the add failed), so `approve`, `rework` and `discuss` work as for a local job. Any reason you copy from its output follows the **Untrusted reason text** rule.
   - PR `CLOSED`: records `pr=<url>`, then `B abort $ID --requeue --reason 'requeue: cloud PR closed without merging'`.
   - A job that left stage `cloud` (or was aborted) meanwhile is skipped, never overwritten.

   Then run the **Cloud-home tail** for every job in `moved` and every id in `arrived`, in this session, one job at a time with `ID=<its id>`.

   **Cloud-home tail** (`/trevskills-scrum cloud-home <id>`: serve.py starts it headless; interactive Sync runs the same steps for every moved or arrived job). The job must be one `B cloud-sync` already moved or listed in `arrived`: `done`, or `needs-human` or `aborted` with a `pr`. Otherwise **refuse** and stop. Load it from `$F/board.json`: `<url>` is its `pr`, `<baseRefName>` is its `base` without `origin/`, and "the worktree add succeeded" means it has a `worktree`. Then run these steps unchanged, in order:
   - **Artifacts home.** For a `MERGED`, `scrum:needs-human` or `CLOSED` PR, right after its `B set` (and before **Schema auto-migrate** starts the detached approve), bring the job folder home. The step fetches into the job's own ref `refs/scrum-home/$ID`, never the shared `FETCH_HEAD`, because serve.py runs several cloud-home sessions at once in the same checkout and a parallel fetch overwrites `FETCH_HEAD` in between. A missing branch means the fetch fails: extract nothing, report no error, and go on. The branch is copied and deleted only when the ref's commit subject is exactly `[scrum $ID] artifacts` (the **Artifacts** push's subject); otherwise the block prints the `artifacts: kept ...` line, the final report quotes it, and the branch stays for a human. The copy never overwrites the local `feature.md`: it copies all but `feature.md`. The branch is deleted only after the copy succeeds, and never force. The ref is always dropped at the end:
     ```bash
     cd "$REPO"; H="refs/scrum-home/$ID"
     if git fetch origin "+refs/heads/scrum-artifacts/${ID}:$H" 2>/dev/null; then
       T=$(mktemp -d)
       if [ "$(git log -1 --format=%s "$H")" != "[scrum $ID] artifacts" ]; then
         echo "artifacts: kept scrum-artifacts/$ID, its commit is not [scrum $ID] artifacts"
       elif git archive "$H" scrum/jobs/$ID 2>/dev/null | tar -x -C "$T" 2>/dev/null && [ -d "$T/scrum/jobs/$ID" ]; then
         rm -f "$T/scrum/jobs/$ID/feature.md" && mkdir -p "$F/jobs/$ID" &&
           cp -R "$T/scrum/jobs/$ID/." "$F/jobs/$ID/" && git push origin --delete scrum-artifacts/$ID
       else git push origin --delete scrum-artifacts/$ID  # an empty artifacts branch: nothing to copy
       fi
       rm -rf "$T"
     fi
     git update-ref -d "$H" 2>/dev/null
     ```
   - **Unreviewed merge.** Then, for a `MERGED` PR whose job `lane` is `fast` or `standard`, when `ls "$F"/jobs/$ID/round-*/review-code.md "$F/jobs/$ID/decision.md" "$F/jobs/$ID/human-approval.md" 2>/dev/null` prints nothing (a session that merged by `gh api` never ran `B set $ID stage=merging`), run `B backlog-add --top -- 'Unreviewed cloud merge: job $ID merged PR <url> with no code review; review that diff on main'` and name it in the final report.
   - **Follow-ups.** Then, as **Approve** step 3 (including its Fallback) does on its own board: when `$F/jobs/$ID/followups/*.md` exist, run `B backlog-spec $ID`, and when it succeeds run `B rank-backlog` once (a `rank-backlog` failure is named in the final report only and never stops the sync); otherwise, when `decision.md` is missing (a fast-lane job has no approver), do the approver's **Out-of-scope follow-ups** from the `## Out of scope` bullets of the latest `round-*/review-*.md` the same way (Rank, then `B backlog-add` one bullet per argument); otherwise, when `decision.md` has a non-empty `## Follow-ups` section that is not just `- none`, drop each bullet whose test file an open `- [ ]` line in `$F/backlog.md` already names (the cloud approver read another board's backlog; jobs 1812, 1822), then run the **Rank** (SKILL.md New job 3c, `jev-gate.py rank`) on each bullet left, then `B backlog-add "<item> (from $ID)" ...`, one argument per bullet (one call per item when ranked items differ in N). Separately, when `decision.md` has a non-empty `## Manual checks` section that is not just `- none`, run `B manual-add "<item> (from $ID)" ...`, one argument per bullet, whatever `## Follow-ups` holds; a failing `manual-add` never blocks the sync. Last, for each test a `round-*/check.md` reports as a load flake (failed in the full run, passed alone or on the re-run) whose name no open `- [ ]` line in `$F/backlog.md` holds, run `B backlog-add '<test file>: <test> fails under full-suite load and passes alone; make it load-safe by waiting on the condition with a deadline, never a fixed sleep (from $ID)'`. Do the same for each test a `round-*/check.md` calls unrelated to the diff for another cause (live machine state, the job id in the worktree path), with `B backlog-add '<test file>: <test> fails from <that cause, no single quotes>, not the diff; make it independent of that cause (from $ID)'`. Spawn no spec writer here.
   - **Schema auto-migrate.** When the job's needs-human reason starts `Hard stop: schema` and the worktree add succeeded, do not leave it for Trevor: start a detached local approve with `B spawn $ID approve --model sonnet`, as **BigBoy lane** step 3 starts a child. Trevor chose this unattended path on purpose, so migrations run locally on a cheap model with nobody watching. `approve` then runs `/trevskills-migrate` and **Merge** exactly as it already does: its main checkout guard and every refusal still apply, and a refusal or a stopped migrate leaves the job `needs-human`. `--model sonnet` on that session is the only model override; never edit any agent's `model:` line.

   When the job is `done` (for interactive Sync: when any moved job went `done`), run **Merge** step 7's **Fast-forward main** once; if it fails, run `B set <each such id> reason='merged, not live: <why>'`. Then, for each such `done` job whose `decision.md` has `## Prod runs` bullets other than `- none`, or, when decision.md is missing, whose `spec.md` does, run **Merge** step 7's **Prod check** with `ID=<its id>` (deploy wait, **Prod runs** through `prod-ok`, smoke check; a failure or retry follows **Migrate**'s Prod check rule; it reads `## Prod runs` from spec.md when decision.md is missing, and its `B set $ID stage=deploying` then `stage=done` bracket it), before the job counts as live: never report `live` for such a job until it passes, and a job whose Prod check fails goes `needs-human` through its `B ask`. Then, for each such `done` job, run **Merge** step 7's **Scrum map** (build.md arrives via **Artifacts home**), then, when the job has a `parent`, **BigBoy chaining** (**BigBoy lane** step 5 with `ID` and `P` its parent); a `needs-human` or `aborted` job with a `pr` runs neither. Then run `B digest-due`, and when it prints `"due": true`, run **Digest**.
