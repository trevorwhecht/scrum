# Shop Mac

## Transport and probe

`skills/trevskills-scrum/shop.py` is the scrum's only way to talk to the shop MacBook Pro (mid 2015, macOS 12). It is stdlib only; serve.py and board.py import it the way serve.py imports `buildlock.py`.

- **Every call starts `ssh shopmac`.** The alias and its key live in `~/.ssh/config`. Options go after the alias (`ssh shopmac -o BatchMode=yes -o ConnectTimeout=5 ...`), where they win over the config file. Never use another remote-exec form.
- **PATH.** A non-interactive ssh shell has only `/usr/bin:/bin:/usr/sbin:/sbin`, so every remote command is prefixed with `export PATH="$HOME/.local/bin:$PATH";` (node, gh and claude live there; git is `/usr/bin/git`).
- **Secrets go through `input`.** `run(cmd, timeout, input=None)` sends `input` on stdin (a `str` as UTF-8, `bytes` unchanged) and never puts it in argv. With no `input`, ssh reads `/dev/null`, never the caller's stdin. stdout and stderr are captured, so ssh's own messages never reach the caller's terminal or log.
- **Failed results, never exceptions.** `run` has a hard subprocess timeout and returns a `CompletedProcess` with `str` output: `124` when the timeout hits, `127` when ssh cannot start, and ssh's own `255` when the connection fails. Output that is not UTF-8 is decoded with replacement.
- **Probe.** `probe()` makes one round trip (`sysctl -n vm.loadavg hw.ncpu; command -v node gh claude; true`, 10 s timeout) and returns `{"up": bool, "load": float | None, "tools": {"node": bool, "gh": bool, "claude": bool}}`. `load` is the 1-minute load as a percent of all cores, `board.cpu_load_pct`'s unit; it is None when the output does not parse. A missing tool never reads as down. The result is cached in-process: an up result for 60 s, a down result for 300 s, so a sleeping shop Mac costs at most one probe of 10 s or less per 5 one-minute watchdog ticks.
- **Down is silent.** When the shop Mac sleeps or is unreachable (exit `255`, `124` or `127`), `probe()` returns `up: false` and prints nothing and raises nothing. Callers skip it quietly: Trevor may be out of town.
- **CLI.** `python3 shop.py probe` prints the probe as one JSON line and exits 0 whether the shop Mac is up or down. Later tickets add their own subcommands and sections here.

## Setup

`python3 shop.py setup` (`setup()`) prepares the shop Mac for a scrum job. It drops the probe and `ready()` caches and takes a fresh probe; a down shop Mac prints `shop: down` and exits 1 with no other ssh call. Otherwise it runs the steps below in order. Each prints one line, `<step>: ok`, `<step>: ok (changed)` or `<step>: failed (exit <n>)`, and remote output is never printed. The CLI exits 1 when a step failed; an account that is `not ready` never fails it. Every step checks before it acts, so a second run prints no `(changed)`. Installs time out at 600 s, account checks at 120 s and every other step at 60 s.

- **node.** When the probe finds no node, one call downloads Node `NODE_VERSION` (darwin-x64) with `curl -fsSL`, checks it with `shasum -a 256 -c` against `NODE_SHA256`, extracts it to `~/.local/share/node-v<version>-darwin-x64` and links `node`, `npm` and `npx` into `~/.local/bin`. It works in a `mktemp -d` dir that is always removed, and a checksum mismatch installs nothing.
- **gh.** The same for gh `GH_VERSION` against `GH_SHA256`, copying `bin/gh` to `~/.local/bin/gh`.
- **gh login.** `ok` when `gh auth status` exits 0. Otherwise this Mac's `gh auth token` goes on stdin to `gh auth login --hostname github.com --git-protocol https --with-token --insecure-storage`, then `chmod 600 ~/.config/gh/hosts.yml`. gh always uses file storage (mode 600) because the shop's login keychain is locked over SSH (`security` exits 36, "User interaction is not allowed"), so a keychain token would fail in the next SSH session. A local `gh auth token` that fails or prints nothing fails the step with no remote call.
- **gh git.** `gh auth setup-git` runs only when `git config --global --get-all credential.https://github.com.helper` lacks `gh auth git-credential`.
- **owa links.** `mkdir -p ~/.claude-owa`, then `~/.claude-owa/<name> -> ~/.claude/<name>` for each `OWA_LINKS` name whose target exists and whose link path is neither a file nor a symlink (a broken link counts). Nothing else there, such as `.claude.json` or `.credentials.json`, is touched.
- **permissions.** `_permissions_script()` goes on stdin to the shop's `python3 -`. It appends the missing `SHOP_PERMISSIONS` entries (allow, deny, ask, additionalDirectories, with `{home}` replaced) to `~/.claude/settings.json`, never removes one, and rewrites the file atomically only on a change. Other keys keep their bytes, and malformed JSON fails the step with nothing written. `SHOP_PERMISSIONS` is this Mac's set without the local-only entries (MCP tools, Chrome, `.env.prod`, Homebrew, PR merge, safe-reset).
- **account main, account owa.** Each `SHOP_ACCOUNTS` account runs `claude -p 'Reply with the single word ok' --model haiku --max-turns 1`: `ok` when it exits 0 and says ok, else `not ready`. Both logins sit in the shop's login keychain, which SSH sessions cannot read, so each account uses a long-lived token made once in the shop's GUI with `claude setup-token` and saved with mode 600 to `~/.claude/oauth-token` (main) or `~/.claude-owa/oauth-token` (owa, which also sets `CLAUDE_CONFIG_DIR="$HOME/.claude-owa"`). `account_env(name)` is the shell prefix that selects the account and loads its token in the shop's own shell, `[ -r F ] && export CLAUDE_CODE_OAUTH_TOKEN="$(cat F)"`, so the token never reaches this Mac; dispatch reuses it. A missing token file prints `not ready (run claude setup-token in the shop GUI)`.

## Ready

`ready()` returns `{"ready", "up", "gh", "node", "claude", "accounts": {"main", "owa"}}`, all bools. `ready` is true when the shop Mac is up, `gh auth status` exits 0, node and claude are in the probe's tools, and at least one account answers. A down shop Mac returns all false at once, with no ssh beyond the probe's cache. An up result is cached for 600 s (`READY_TTL`), so a gh logout or a revoked token can go unseen that long; `setup()` clears the cache. It prints nothing.

## Env copy

`env_copy(project, repo)` copies `<repo>/.env.local`, and no other env file, to the shop's `~/scrum-work/<project>/.env.local`. It is one `run()` of `umask 077 && mkdir -p ... && cat > .env.local.tmp && mv -f ...` with the file's bytes only on stdin, so the copy is mode 600 in a mode 700 folder and never in argv. It returns `copied`, `none` (no `.env.local`; no ssh) or `failed` (a project name not matching `[A-Za-z0-9][A-Za-z0-9._-]*`, with no ssh; a down shop Mac; a failed copy), and prints and logs nothing. `mkdir -p` makes the project folder before any clone, so dispatch clones into that folder or copies after the clone.

## E2E channel

The shop Mac has Google Chrome but no Playwright Chromium. With `SCRUM_PW_CHANNEL` set (e.g. `chrome`), `board.py e2e-specs` adds `--config "$HOME/.claude/skills/trevskills-e2e/channel.config.mjs"` to its `command` before the spec files (after `--` for `npm run`), and the Check gate's debug exception adds it to its `npx playwright test`. Run from the repo root, the wrapper loads the repo's first `playwright.config.{ts,js,mts,mjs,cts,cjs}`, sets `use.channel` on its chromium projects (the top-level `use` when it has none), and resolves the config's relative paths (testDir, outputDir, snapshotDir, globalSetup and globalTeardown, tsconfig, webServer `cwd`, reporter output) against the repo, so no project repo is edited. Unset or blank, every command is byte-identical to before.

## MD sync

`md_sync()` makes this Mac the single writer of what shop sessions read: the skill clones, `~/.claude/CLAUDE.md` and the memory notes. Dispatch calls it before every shop dispatch and skips the dispatch on `False`. It prints nothing. `python3 shop.py md-sync` prints one line, `md-sync: ok` (exit 0), `md-sync: failed` or `shop: down` (exit 1), and never remote output.

- **Local reads first.** This Mac's CLAUDE.md and memory dirs are read before any ssh, so a missing `~/.claude/CLAUDE.md` returns `False` with no call. A down probe returns `False` with no other call.
- **Three calls, in order, 60 s each.** A non-zero exit returns `False` at once and runs no later call.
  1. `git -C ~/code/scrum pull --ff-only && git -C ~/code/trevorhecht-skills pull --ff-only`: the clones that the shop's `~/.claude` skills, agents and rules link to. A pull that is not a fast-forward, or that a dirty clone blocks, fails the sync; nothing is ever reset.
  2. The one-time cleanup below.
  3. One tar stream on stdin, unpacked in a temp dir under `~/.claude`. `CLAUDE.md` is this Mac's bytes, a newline when they lack one, then `@~/code/scrum/skills/trevskills-scrum/shop/machine-notes.md` (the shop's facts and its no-writes rule). It replaces the shop's by rename, so a symlink there becomes a file. Then every `~/.claude/projects/*/memory` dir is removed and each synced project's memory dir is moved in, so anything a shop session wrote is dropped. Other files beside `memory/` (session logs) stay.
- **Synced projects.** Each `projects.json` entry (`SCRUM_REGISTRY` honoured) with a `scrum/` dir whose folder name matches `[A-Za-z0-9][A-Za-z0-9._-]*` and is not shared by another entry. A project with no memory dir here has none on the shop.
- **Key rule.** Claude Code names a project's dir under `~/.claude/projects/` after its path, with every character outside `[A-Za-z0-9]` replaced by `-` (`memory_key()`). This Mac's `projects/<key of the repo>/memory/` becomes the shop's `projects/<key of $HOME/scrum-work/<name>>/memory/`. The shop's own shell works that key out from its `$HOME` with `tr`, so no shop user name is in this code. Dispatch must clone into `~/scrum-work/<name>` and start sessions there for the keys to line up.
- **One-time cleanup.** While `~/.md-sync-cleanup-done` is missing, the shop's own `~/.claude/CLAUDE.md` and every `projects/<key>/memory` are copied, and `~/MACHINES.md`, `~/code/scrum-multi-machine-spec.md` and `~/scrum-probe` are moved, into `~/md-sync-backup-<YYYY-MM-DD>`. A missing item is skipped. Then the marker is written. When the backup folder cannot be made, nothing is moved, no marker is written and the sync fails. Nothing restores or prunes the backup.
- **No shop writes.** `SHOP_PERMISSIONS["deny"]` holds `Edit(/{home}/.claude/CLAUDE.md)`, `Edit(/{home}/.claude/rules/**)` and `Edit(/{home}/.claude/projects/*/memory/**)`, and the same three under `.claude-owa`; `setup()` merges them. The machine notes tell sessions never to write memory notes, rules or CLAUDE.md and to put what they learn in the job's follow-ups.
- **Auto memory stays on.** `autoMemoryEnabled: false` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY` would also stop Claude reading the memory dir, which would make the copy useless. The deny rules, the notes and the replacement on every sync stand in for them.
