# Shop Mac

## Transport and probe

`skills/trevskills-scrum/shop.py` is the scrum's only way to talk to the shop MacBook Pro (mid 2015, macOS 12). It is stdlib only; serve.py and board.py import it the way serve.py imports `buildlock.py`.

- **Every call starts `ssh shopmac`.** The alias and its key live in `~/.ssh/config`. Options go after the alias (`ssh shopmac -o BatchMode=yes -o ConnectTimeout=5 ...`), where they win over the config file. Never use another remote-exec form.
- **Workers.** `shop.workers()` reads `workers.txt` beside `projects.json` (`SCRUM_REGISTRY` honoured; default `~/.claude/trevskills-scrum/workers.txt`). Each line is `<alias> <max jobs> <account>[,<account>...]`, split on whitespace; text from `#` on and blank lines are ignored. A line is skipped, and the rest still load, when it lacks exactly 3 fields, its alias does not fullmatch `[A-Za-z0-9][A-Za-z0-9._-]*` (so never `-`-led), its max does not fullmatch `[1-9][0-9]*`, an account is empty, repeated or not in `SHOP_ACCOUNTS`, or an earlier line has the alias. A missing file means `shopmac 2 owa,main`; a file with no valid line, or one that cannot be read, means no workers, so dispatch is off. The `trevskills-link-mac` skill appends a linked Mac's line. Every function that makes an ssh call takes `alias=` (default `shopmac`) and runs `ssh <alias>`; `run()` refuses an alias off that pattern with `127` and no ssh. The probe and `ready()` caches are kept per alias, and `setup()` and `ready()` check only the accounts on that worker's line.
- **PATH.** A non-interactive ssh shell has only `/usr/bin:/bin:/usr/sbin:/sbin`, so every remote command is prefixed with `export PATH="$HOME/.local/bin:$PATH";` (node, gh and claude live there; git is `/usr/bin/git`).
- **Secrets go through `input`.** `run(cmd, timeout, input=None)` sends `input` on stdin (a `str` as UTF-8, `bytes` unchanged) and never puts it in argv. With no `input`, ssh reads `/dev/null`, never the caller's stdin. stdout and stderr are captured, so ssh's own messages never reach the caller's terminal or log.
- **Failed results, never exceptions.** `run` has a hard subprocess timeout and returns a `CompletedProcess` with `str` output: `124` when the timeout hits, `127` when ssh cannot start, and ssh's own `255` when the connection fails. Output that is not UTF-8 is decoded with replacement. Under unittest, unless a test replaced `subprocess.run`, it returns `127` with no ssh, so a watchdog test never reaches the real shop Mac.
- **Probe.** `probe()` makes one round trip (`sysctl -n vm.loadavg hw.ncpu; command -v node gh claude; true`, 10 s timeout) and returns `{"up": bool, "load": float | None, "tools": {"node": bool, "gh": bool, "claude": bool}}`. `load` is the 1-minute load as a percent of all cores, `board.cpu_load_pct`'s unit; it is None when the output does not parse. A missing tool never reads as down. The result is cached in-process: an up result for 60 s, a down result for 300 s, so a sleeping shop Mac costs at most one probe of 10 s or less per 5 one-minute watchdog ticks.
- **Down is silent.** When the shop Mac sleeps or is unreachable (exit `255`, `124` or `127`), `probe()` returns `up: false` and prints nothing and raises nothing. Callers skip it quietly: Trevor may be out of town.
- **CLI.** `python3 shop.py probe` prints the probe as one JSON line and exits 0 whether the shop Mac is up or down. `probe`, `setup` and `md-sync` take an optional `[alias]`, default the first `workers.txt` alias (`shopmac` when there is none). Later tickets add their own subcommands and sections here.

## Setup

`python3 shop.py setup` (`setup()`) prepares the shop Mac for a scrum job. It drops the probe and `ready()` caches and takes a fresh probe; a down shop Mac prints `shop: down` and exits 1 with no other ssh call. Otherwise it runs the steps below in order. Each prints one line, `<step>: ok`, `<step>: ok (changed)` or `<step>: failed (exit <n>)`, and remote output is never printed. The CLI exits 1 when a step failed; an account that is `not ready` never fails it. Every step checks before it acts, so a second run prints no `(changed)`. Installs time out at 600 s, account checks at 120 s and every other step at 60 s.

- **node.** When the probe finds no node, one call downloads Node `NODE_VERSION` (darwin-x64) with `curl -fsSL`, checks it with `shasum -a 256 -c` against `NODE_SHA256`, extracts it to `~/.local/share/node-v<version>-darwin-x64` and links `node`, `npm` and `npx` into `~/.local/bin`. It works in a `mktemp -d` dir that is always removed, and a checksum mismatch installs nothing.
- **gh.** The same for gh `GH_VERSION` against `GH_SHA256`, copying `bin/gh` to `~/.local/bin/gh`.
- **gh login.** `ok` when `gh auth status` exits 0. Otherwise this Mac's `gh auth token` goes on stdin to `gh auth login --hostname github.com --git-protocol https --with-token --insecure-storage`, then `chmod 600 ~/.config/gh/hosts.yml`. gh always uses file storage (mode 600) because the shop's login keychain is locked over SSH (`security` exits 36, "User interaction is not allowed"), so a keychain token would fail in the next SSH session. A local `gh auth token` that fails or prints nothing fails the step with no remote call.
- **gh git.** `gh auth setup-git` runs only when `git config --global --get-all credential.https://github.com.helper` lacks `gh auth git-credential`.
- **owa links.** `mkdir -p ~/.claude-owa`, then `~/.claude-owa/<name> -> ~/.claude/<name>` for each `OWA_LINKS` name whose target exists and whose link path is neither a file nor a symlink (a broken link counts). Nothing else there, such as `.claude.json` or `.credentials.json`, is touched.
- **permissions.** `_permissions_script()` goes on stdin to the shop's `python3 -`. It appends the missing `SHOP_PERMISSIONS` entries (allow, deny, ask, additionalDirectories, with `{home}` replaced) to `~/.claude/settings.json`, never removes one, and rewrites the file atomically only on a change. It also appends one `hooks.PostToolUse` entry running `EDIT_CHECK_CMD` (edit-check.py, guarded by `if [ -f ... ]` so it is a no-op outside a scrum-repo clone) unless `edit-check` already appears in that list. Other keys keep their bytes, and malformed JSON, a non-object `hooks` or a non-list `PostToolUse` fails the step with nothing written. `SHOP_PERMISSIONS` is this Mac's set without the local-only entries (MCP tools, Chrome, `.env.prod`, Homebrew, PR merge, safe-reset).
- **account main, account owa.** Each `SHOP_ACCOUNTS` account runs `claude -p 'Reply with the single word ok' --model haiku --max-turns 1`: `ok` when it exits 0 and says ok, else `not ready`. Both logins sit in the shop's login keychain, which SSH sessions cannot read, so each account uses a long-lived token made once in the shop's GUI with `claude setup-token` and saved with mode 600 to `~/.claude/oauth-token` (main) or `~/.claude-owa/oauth-token` (owa, which also sets `CLAUDE_CONFIG_DIR="$HOME/.claude-owa"`). `account_env(name)` is the shell prefix that selects the account and loads its token in the shop's own shell, `[ -r F ] && export CLAUDE_CODE_OAUTH_TOKEN="$(cat F)"`, so the token never reaches this Mac; dispatch reuses it. A missing token file prints `not ready (run claude setup-token in the shop GUI)`.
- **ruff.** `ok` when `command -v ruff` finds it. Otherwise `PYTHONUSERBASE="$HOME/.local" /usr/bin/python3 -m pip install --user -q ruff` (no Homebrew on the shop; the binary lands in `~/.local/bin`, on the PATH prefix) so edit-check.py's `ruff check --select F` runs there. The system Python, because a bare `python3` under the PATH prefix is uv's externally-managed one, which refuses `pip install --user`. ruff is in `OPTIONAL_STEPS`: a failed ruff step still prints `ruff: failed`, but never stops a dispatch.
- **jev key.** `ok` when `[ -s ~/.config/typesafe/key ]` holds on the shop (an empty file counts as missing), with no Keychain read here. Otherwise this Mac's Keychain item TypeSafe/typesafe (`/usr/bin/security find-generic-password -s TypeSafe -a typesafe -w`, the item `jev.api_key` reads) goes on stdin to `umask 077 && mkdir -p ~/.config/typesafe && cat > ~/.config/typesafe/key.tmp && mv -f ...`, so the file is mode 600 and the key never reaches argv, output or a log. A local read that fails, times out or prints nothing fails the step with no remote call. Jev cannot read the shop's keychain over SSH either, so `start()` loads the key in the shop's own shell, `[ -r F ] && export TYPESAFE_API_KEY="$(cat F)"`, before `nohup claude`; with no file nothing is exported and jev degrades as it does with no key.

## Ready

`ready()` returns `{"ready", "up", "gh", "node", "claude", "accounts": {"main", "owa"}}`, all bools. `ready` is true when the shop Mac is up, `gh auth status` exits 0, node and claude are in the probe's tools, and at least one account answers. A down shop Mac returns all false at once, with no ssh beyond the probe's cache. An up result is cached for 600 s (`READY_TTL`), so a gh logout or a revoked token can go unseen that long; `setup()` clears the cache. It prints nothing.

## Env copy

`env_copy(project, repo)` copies `<repo>/.env.local`, and no other env file, to the shop's `~/scrum-work/<project>/.env.local`. It is one `run()` of `umask 077 && mkdir -p ... && cat > .env.local.tmp && mv -f ...` with the file's bytes only on stdin, so the copy is mode 600 in a mode 700 folder and never in argv. It returns `copied`, `none` (no `.env.local`; no ssh) or `failed` (a project name not matching `[A-Za-z0-9][A-Za-z0-9._-]*`, with no ssh; a down shop Mac; a failed copy), and prints and logs nothing. `mkdir -p` makes the project folder before any clone, so dispatch clones into that folder or copies after the clone.

`profile_copy(project, repo)` gives the shop clone this Mac's project profile, so a cloud-job session there keeps the `E2E:`, `Test sign-in:`, `Render auth:` and `Visual mask:` lines (lanes/cloud.md **Setup** keeps the file). Dispatch runs it right after `env_copy()`. It reads `<repo>/scrum/project.md` and the Render auth file before any ssh, then runs one probe and up to two `run()` calls of 60 s, each with its bytes only on stdin, and prints nothing.

- **Profile.** The repo path, as given and as its realpath, becomes `<shop $HOME>/scrum-work/<project>` when a `/`, a character outside `[A-Za-z0-9._-]` or the end of the text follows it, so `<repo>-old/x` is not the repo. Then every other `<this Mac's home>/` becomes `<shop $HOME>/`: the text carries `HOME_TOKEN` and the shop's own `sed` puts its `$HOME` there, so no shop user name is in the code. Every other byte is unchanged. It is written with tmp file + `mv -f` to `~/scrum-work/<project>/scrum/project.md`, replacing whatever a shop session wrote there.
- **Exclude lines.** The same call adds setup step 2's `scrum/` and `.claude/worktrees/` lines to the clone's `.git/info/exclude`, each once. When `~/scrum-work/<project>/.git` is not a directory it writes nothing and fails, so no fake `.git` breaks the next `clone()`.
- **Render auth.** A `- Render auth:` path (the first such line, trimmed) is read from a job worktree, as `lanes/review.md` does: `posixpath.normpath(".claude/worktrees/scrum-x/" + <path>)`. When the result does not start with `..`, is not absolute, is not under `.claude/`, fullmatches `[A-Za-z0-9._/-]+` and is a file here, a second call copies it to the same repo-relative path in the clone with `umask 077 && mkdir -p ... && cat > <path>.tmp && mv -f ...`, so the file is mode 600 and new folders 700 (`../../../playwright/.auth/admin.json` becomes `playwright/.auth/admin.json`). Any other path, or none, skips the call and its bytes are never read.
- **Result.** It returns `copied` when the profile call, and the auth call when it runs, exit 0; `none` (no `scrum/project.md` here; no ssh); or `failed`: with no ssh for a project name off `[A-Za-z0-9][A-Za-z0-9._-]*`, after only the probe for a down shop Mac, and for no clone there or a call that exits non-zero or times out.

## E2E channel

The shop Mac has Google Chrome but no Playwright Chromium. With `SCRUM_PW_CHANNEL` set (e.g. `chrome`), `board.py e2e-specs` adds `--config "$HOME/.claude/skills/trevskills-e2e/channel.config.mjs"` to its `command` before the spec files (after `--` for `npm run`), and the Check gate's debug exception adds it to its `npx playwright test`. Run from the repo root, the wrapper loads the repo's first `playwright.config.{ts,js,mts,mjs,cts,cjs}`, sets `use.channel` on its chromium projects (the top-level `use` when it has none), and resolves the config's relative paths (testDir, outputDir, snapshotDir, globalSetup and globalTeardown, tsconfig, webServer `cwd`, reporter output) against the repo, so no project repo is edited. Unset or blank, every command is byte-identical to before.

`clone()` also sets `hasTrustDialogAccepted` for the clone's folder in the shop's `~/.claude-owa/.claude.json` and `~/.claude.json` (each that exists; mode 600), so the project's `.claude/settings.json` permissions apply in shop sessions.

## MD sync

`md_sync()` makes this Mac the single writer of what shop sessions read: the skill clones, `~/.claude/CLAUDE.md`, the memory notes and this Mac's plain skill folders. Shop dispatch (below) calls `md_sync()` first, before any other shop step, and skips the dispatch on `False`. It prints nothing. `python3 shop.py md-sync` prints one line, `md-sync: ok` (exit 0), `md-sync: failed` or `shop: down` (exit 1), and never remote output.

- **Local reads first.** This Mac's CLAUDE.md, memory dirs and skill folders are read before any ssh, so a missing `~/.claude/CLAUDE.md` returns `False` with no call. A down probe returns `False` with no other call.
- **Three calls, in order, 60 s each.** A non-zero exit returns `False` at once and runs no later call.
  1. `git -C ~/code/scrum pull --ff-only && git -C ~/code/trevorhecht-skills pull --ff-only`: the clones that the shop's `~/.claude` skills, agents and rules link to. A pull that is not a fast-forward, or that a dirty clone blocks, fails the sync; nothing is ever reset.
  2. The one-time cleanup below.
  3. One tar stream on stdin, unpacked in a temp dir under `~/.claude`. `CLAUDE.md` is this Mac's bytes, a newline when they lack one, then `@~/code/scrum/skills/trevskills-scrum/shop/machine-notes-<alias>.md` (that worker's own facts and the no-writes rule; a worker with no such file in this repo gets no import line, so add one file per new worker Mac). It replaces the shop's by rename, so a symlink there becomes a file. Then every `~/.claude/projects/*/memory` dir is removed and each synced project's memory dir is moved in, so anything a shop session wrote is dropped. Other files beside `memory/` (session logs) stay. Last, each skill folder (below) replaces the shop's `~/.claude/skills/<name>`.
- **Skill folders.** Every entry of this Mac's `~/.claude/skills/` that is a real folder (not a link), is not `synced` and has a name matching `[A-Za-z0-9][A-Za-z0-9._-]*` is copied to the shop's `~/.claude/skills/<name>`, which is removed first, so a shop link or an older copy by that name is replaced (a shop link's target stays). Shop skills this Mac has no folder for are left alone. A link inside a copied folder arrives as a regular file; a broken link is skipped. Plain folders reach no git clone (e.g. `trevskills-email`, whose `ai-tells.md` project code reads), so this copy is how the shop gets them. With no plain folder here, the copy touches no shop skill and makes no `~/.claude/skills` dir.
- **Synced projects.** Each `projects.json` entry (`SCRUM_REGISTRY` honoured) with a `scrum/` dir whose folder name matches `[A-Za-z0-9][A-Za-z0-9._-]*` and whose key (below) no other such entry shares: `app.one` and `app-one` would land in one shop dir, so neither syncs. A project with no memory dir here has none on the shop.
- **Key rule.** Claude Code names a project's dir under `~/.claude/projects/` after its path, with every character outside `[A-Za-z0-9]` replaced by `-` (`memory_key()`). This Mac's `projects/<key of the repo>/memory/` becomes the shop's `projects/<key of $HOME/scrum-work/<name>>/memory/`. The shop's own shell works that key out from its `$HOME` with `tr`, so no shop user name is in this code. Dispatch must clone into `~/scrum-work/<name>` and start sessions there for the keys to line up.
- **One-time cleanup.** While `~/.md-sync-cleanup-done` is missing, the shop's own `~/.claude/CLAUDE.md` and every `projects/<key>/memory` are copied, and `~/MACHINES.md`, `~/code/scrum-multi-machine-spec.md` and `~/scrum-probe` are moved, into `~/md-sync-backup-<YYYY-MM-DD-HHMMSS>`. A missing item is skipped. Then the marker is written. When the backup folder cannot be made, nothing is moved, no marker is written and the sync fails. Nothing restores or prunes the backup.
- **No shop writes.** `SHOP_PERMISSIONS["deny"]` holds `Edit(/{home}/.claude/CLAUDE.md)`, `Edit(/{home}/.claude/rules/**)` and `Edit(/{home}/.claude/projects/*/memory/**)`, and the same three under `.claude-owa`; `setup()` merges them. The machine notes tell sessions never to write memory notes, rules or CLAUDE.md and to put what they learn in the job's follow-ups.
- **Auto memory stays on.** `autoMemoryEnabled: false` and `CLAUDE_CODE_DISABLE_AUTO_MEMORY` would also stop Claude reading the memory dir, which would make the copy useless. The deny rules, the notes and the replacement on every sync stand in for them.

## Dispatch

`serve.py` `shop_tick(project, repo, root)` runs on every watchdog tick right after `cloud_tick`, in its own try guard (an error prints `watchdog: <project>: shop: <error>` and the tick goes on), and sends at most one job per call.

- **When.** Whenever a worker has a free slot, whether or not this Mac's machine guard (`machine_ok`, `cpu_hot()`) is holding the job; this Mac's cool-down does not stop the shop. Each worker has its own cool-down instead: its Cool down button in the meter (POST /api/cooldown with its alias) creates `cooldown-<alias>` beside the cool-down flag (`board.cooldown_path(alias)`), and while it exists that worker gets no new work and is never probed; its started jobs finish. The job goes to the first `workers()` worker, in file order, that is out of its backoff, not cooled, has fewer than its max jobs in stage cloud with a `shop` pid across every project's board (a job with no `worker` field counts as `shopmac`), is `ready(alias)` and has an account below; a later worker is never probed. With no such worker, a sleeping one included, nothing is sent, with no output and no board change.
- **Pool.** `held_work()`, the jobs idle_claim would start: a queued launch with action `start` and the waiting children, lowest numeric id first. Never a paused job, a lilguy job (board lane `lilguy`, `Lane: lilguy` anywhere in feature.md, or a `lilguy-fit.json` with `fit: true` on a job with no parent or a Run-all parent: the local lilguy route takes it, and a shop run would leave the clone on a job branch with no artifacts pushed), a launch with setup pending, a job whose feature.md names `digests/<NNN>/proposals.json`, nor any job of a project whose project.md has a `- Base branch:` line or mentions docker (any case). A queued launch whose Likely files overlap a running or cloud job (`busy_files`, `clear_of_busy`, the same check idle_claim uses) is skipped for the next pool entry; a launch with unreadable files goes only while nothing is busy. A waiting child gets its overlap check from `cmd_ready`. A job that `board.tag_runs_on` tags `main` is skipped for the next pool entry.
- **New work** (job 1141). With nothing in the pool, or only `main` jobs, the shop claims new work by `auto_continue_tick`'s rules, held work always first: only a project with an `- Auto continue:` line, its run-all not running, a claimable backlog line and no `finish_first` hold; none of these met means no shop call. After the worker and account pick, `board.cmd_next(root, shop=<filter>)` claims the top item under the board lock, so this Mac's run-all never takes the same one; cool-down never refuses it. The filter skips an item with `Lane: lilguy` in its text or its pre-written spec's header, one naming `digests/<NNN>/proposals.json`, one whose text or pre-written spec names a `## Cannot run` term (`names_main_only`; no Jev under the lock), and one whose files (`board.text_files` of its pre-written spec, else of its text) are not `clear_of_busy`. A fresh claim that `tag_runs_on` still tags `main` (Jev, asked after the lock) is skipped: it becomes a queued `start` launch here, with no line and no backoff. The job is `started_by` `shop` (the pulse's Claims during cool down never counts it), its feature.md is the item's text, and the steps below run as for a launch.
- **Runs on.** (job 1155) Every job carries a board `runs_on` tag: `any`, `main` or `shop`. A `Runs on: any|main|shop` line above feature.md's first `## ` heading always wins. Without one, `board.tag_runs_on` decides once and stores it: `any` when no worker's `machine-notes-<alias>.md` has a `## Cannot run` list; else Jev is asked whether the job needs something on that list (`main` or `any`), and when Jev is unsure or down, `main` if the text names a list term as a whole word. Jev is asked only outside the board lock and only while a worker has room. Each watchdog tick, before the per-project loop and again after a dispatch, serve.py's `write_shop_room()` writes `shop-room.json` beside `projects.json` (`{"at", "workers"}`: the workers the pick below would take, from the cached probes, no extra ssh); `board.shop_room` reads it as room only when it is at most 180 s old, lists a worker and the project is not excluded above. With room, a local `cmd_ready` leaves an `any` waiting child to the shop for up to 300 s (`shop_first_since`, cleared by a claim) and still claims its `main` siblings; a lilguy or digest child, and one left past 300 s, is claimed here. A `shop` job never starts on this Mac: `cmd_ready` without `shop=` never claims it, and `idle_claim`, `play_queue_tick` and a Start now click (serve.py `Handler.route` `resume`, which replies queued) leave its queued start for the shop. A `main` job is never sent to the shop.
- **Account.** `pick_account`'s own order (soonest seven-day reset first, reserve and limit marks apply), so main takes over when OWA's week resets; when that account is not on the worker's line or not ready there, `prefer=` each of the worker's accounts in its listed order, until one is on its line and its `ready()` account is true.
- **Steps, in order.** A child is claimed first with `cmd_ready(root, parent, live, shop=<id>)`: that one child, with the file-overlap check and no machine check. Then, each with `alias=` that worker, `md_sync()`, `setup()` (no failed step outside `OPTIONAL_STEPS`, and `account <name>` ok), `clone(<repo folder>, <origin URL>)`, `env_copy()` (copied or none), `profile_copy()` (copied or none) and `start()` (clone first checks out origin's default branch in an existing clone: a clean clone left on a job branch; a dirty one fails, nothing is reset or deleted; then it fast-forwards) with the prompt `/trevskills-scrum cloud-job <id> ` plus feature.md (and `## Pre-written spec` with spec.md when it exists) on the job's orchestrator model. The job is then set `stage=cloud shop=<pid> account=<name>` and `worker=<alias>` (the worker it runs on), expecting the stage it was claimed in, and a launch is unqueued; stdout gets `shop: <project>: <id>: started on <alias> (pid <pid>, account <name>)`. `board.py set <id> shop=` takes digits only, and `worker=` the alias pattern.
- **A failed step** puts a claimed child back to waiting and removes its claimed-at.txt (a launch keeps its fields; a fresh claim is left a queued `start` launch, held work for a later shop tick or this Mac's `play_queue_tick`, which cool-down parks), prints one `shop: <project>: <id>: <step> failed on <alias>` line and holds that worker for 600 s (`SHOP_RETRY_AT[<alias>]`, `SHOP_RETRY_EVERY`); other workers still take jobs. A refused mark, or a local session that started the job meanwhile, runs `kill <pid>` on that worker and prints one line.
- **Remote session.** `claude -p --permission-mode acceptEdits` under nohup in `~/scrum-work/<project>`, with `SCRUM_SHOP=1`, `SCRUM_PW_CHANNEL=chrome`, `CLAUDE_NOTIFIER_DISABLE=1`, `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS=0`, the account's `account_env` and `TYPESAFE_API_KEY` when setup's **jev key** file is there. The prompt goes only on stdin, into `.git/scrum-shop/<id>.prompt` (umask 077); the log is `.git/scrum-shop/<id>.log`, inside the clone's `.git` so its worktree stays clean.
- **Results come home through GitHub.** The session opens its PR as any cloud job does and `cloud_tick` syncs it; idle_claim counts a stage-cloud job as busy, so its likely files stay held here. Before each sync, every stage-cloud job with a `shop` pid asks `ended()` on its own `worker` (no field: `shopmac`). One whose session ended and that is still in stage cloud after the sync (no PR moved it) is aborted with `requeue: shop session ended without a PR`, requeued unless a child, and once that abort took effect its open unlabelled `[scrum <id>]` PR from this repo's own `scrum/<id>` is closed (`PATCH state=closed`; a gh failure prints `PR close failed` and the job stays aborted), so the rerun opens no duplicate PR; a usage-limit line in its log tail first marks its account limited (`note_limit`). A down shop Mac reads as still running, so its jobs stay in cloud.
