# New job

1. `ID=$(B new "<title>")`. The title is the feature's first line, at most 60 characters.
   1b. Write the full feature text to `$F/jobs/$ID/feature.md`. You may add `Lane: <lane> — <reason>` and `Complex: yes|no — <reason>` lines under its title.
   1c. **Askme** (only for `askme` or `start <id> askme`; otherwise skip to step 2). An interactive question round with Trevor, run like **discuss**. **Record your terminal** first. Read `feature.md`, `$F/project.md` and just enough of the repo to know what is unclear. The level sets how many questions; you pick the number within it:
      - level 1 asks only what blocks the build;
      - level 2 asks a moderate number;
      - level 3 is thorough.

      Ask in rounds, in plain words. When an answer is unclear, or contradicts another answer, ask follow-up or different questions before going on. Until the questions are done, spawn no agent, create no worktree and edit no file except `feature.md`. Then append to `$F/jobs/$ID/feature.md`, with one pair per question asked, follow-ups included:
      ```
      ## Q&A
      - Q: <question>
        A: <Trevor's answer>
      ```
      If Trevor says to skip or stop, write the pairs answered so far (nothing at all if there are none) and carry on. The same session then runs the rest of the job (step 2 onward).
2. **Base:** first **record your terminal** (Setup). Then run `git fetch origin`. Read the optional base branch: `BB=$(sed -n 's/^- Base branch: *//p' "$F/project.md" | head -1 | sed 's/[[:space:]]*$//')`.
   - **`BB` empty (line missing or blank):** `DEFAULT=$(git symbolic-ref --short refs/remotes/origin/HEAD | sed 's#^origin/##')`. If `symbolic-ref` fails (no `origin/HEAD`), run `git remote set-head origin -a` and try `symbolic-ref` again.
   - **`BB` set:** if it does not match `^[A-Za-z0-9._/-]+$`, run `B ask $ID "Base branch line in the project profile is malformed, so the job cannot tell which branch to start from; fix or remove that line, then pick Carry on." --a "Carry on=resume $ID" --b "Remove this job=abort $ID --cascade" --title WRONG_BRANCH --recommend <key> '<why>'` and stop before the spec writer. If `git rev-parse --verify -q "origin/$BB"` fails, run `B ask $ID 'Base branch <BB> not found on origin, so the job has no branch to start from; push it to GitHub or remove the Base branch line from the project profile, then pick Carry on.' --a "Carry on=resume $ID" --b "Remove this job=abort $ID --cascade" --title WRONG_BRANCH --recommend <key> '<why>'` and stop before the spec writer. Otherwise `DEFAULT=$BB`.

   Then `BASE=origin/$DEFAULT`. Run `B set $ID base=$BASE`.
3. **Spec:** **Model:** only when `$F/jobs/$ID/feature.md` exists, outside a `lilguy` or `cloud` lane session, pick two models once per job, each reusing `jev.log`'s decision, else running `python3 ~/.claude/skills/trevskills-scrum/jev-gate.py spec-model $F/jobs/$ID` (Bash timeout 90000) for every `scrum-spec-writer` spawn of this step (first, respawn, `Refresh spec.md:`), or `jev-gate.py model` the same way for step 5's `scrum-builder`. On `sonnet` or `opus`, pass Agent override `model: "<word>"` to that agent; else no override (Opus). `B fable-ok $ID spec-writer` output other than `none` replaces that override on this step's spec-writer spawns (never step 5's builder); if the Agent tool rejects it, respawn once without it. **Lilguy route:** for a job with no `parent` or a `runall` parent, outside a Cloud lane session, run `B lilguy-fit $ID` (it honours feature.md's `Lane:` line); when `fit` is true, run the **Lilguy lane** instead of the rest of New job. Then, if `$F/jobs/$ID/spec.md` already exists (pre-written from the backlog), the Model decision still runs; skip both spec-writer spawns below and go straight to 3b and 3c; never skip when step 3 runs with **BigBoy lane** step 4's `Refresh spec.md:` line, which spawns over the existing spec.md. Otherwise, when the job's `lane` on the board is `fast` and `feature.md` exists, spawn no spec writer: run `cp $F/jobs/$ID/feature.md $F/jobs/$ID/spec.md` and go to 3b and 3c. Otherwise spawn `scrum-spec-writer` (see **Routing**) and wait for it. Prompt:
   ```
   JOB_DIR=$F/jobs/$ID
   WORKTREE=none
   BASE=$BASE
   ROUND=0
   PROJECT=$F/project.md
   Write spec.md for this job.
   ```
   If `spec.md` is missing afterwards, spawn it once more; if still missing, run `B abort $ID --requeue --reason 'requeue: spec writer produced nothing'` and stop (see **Auto-abort instead of needs-human**). After each spawn, record it: `B set $ID specwriter=<id>` (the returned agent id).
   3b. **Obsolete:** if the first line of `spec.md` starts with `OBSOLETE:` (`head -1 "$F/jobs/$ID/spec.md" | grep -q '^OBSOLETE:'`), the request needs no change, so abort the job yourself. Strip any single quotes from the rest of that line. When that rest starts `needs Trevor`, first run `B manual-add '<rest of the line> (from $ID)'` so the item lands on Trevor's manual checklist; a failing `manual-add` is named in the final report only. Then run `B abort $ID --reason 'obsolete: <rest of that line>'` and stop: create no worktree and spawn no builder. The final report says the job was auto-aborted as obsolete and why.
   3c. **Lane:** **Project .claude/ files** first: outside a **Cloud lane** session, run `B claude-paths $ID`. When `paths` is non-empty and `headless` is true, run `B claude-batch $ID`: on `only` true, `claude-batch` moved the job's dependents' `depends_on` to the batch; run `B abort $ID --reason 'moved to Terminal batch <batch>'` and stop; else carry on. A job titled `Terminal batch: project .claude edits`, or a failing `claude-batch`, instead runs `B ask $ID 'project .claude edits: Claude Code refuses those edits in a session that runs on its own; approve each in a Terminal window.' --a "Run it in a Terminal window=lilguy $ID" --b "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend a 'Trevor always runs these in a Terminal window'` and stops. Otherwise carry on: take the lane word from the `Lane:` line in `$F/jobs/$ID/feature.md` above its first `## ` when its first word is `fast`, `standard`, `debug`, `bigboy` or `lilguy` (any case; `lilguy` counts as `fast`), else from `spec.md`'s `Lane:` line (any other feature.md line is ignored), and run `B set $ID lane=<fast|standard|debug|bigboy>`. Set `lane=debug` when the chosen word is `debug`, and `lane=bigboy` when it is `bigboy`, whatever the other header lines say; the job then goes to the **BigBoy lane** and gets no worktree (skip steps 4-6). This holds for a job with no `parent`, and for a job whose `parent` has no `parent` of its own (a **Run all** child or a BigBoy child): a too-big child becomes a BigBoy itself, never with `B ask` and never with `abort --requeue`, and the planner's tickets become its own children. A job whose `parent` has a `parent` (a child of a converted child) stays one job: for it, `Lane: bigboy` counts as `standard`. Set `fast` only when the chosen word is `fast` and the `Hard stops:` line is `none`. Else set `standard`, also for a missing or malformed line.
      **Human setup:** then, when the job has no `parent` or its parent's `lane` is `runall` (a **Run all** child; so this skips a BigBoy child, whose planner ticket carries its own `Human setup:`), its lane is not `bigboy`, this is not a **Cloud lane** job session, `spec.md`'s `Human setup:` line is present and not `none`, and its `## Waiting on setup` section has a non-empty line, park the deferred part in the backlog: remove every `'` from the `Human setup:` value and from that line, run the **Dupe check** and **Rank** below on it, then `B backlog-add --setup='<Human setup value>' [--priority N] -- '<that line> (from $ID)'`. Then continue the job. A missing or `none` line, or a missing or empty `## Waiting on setup` section, adds nothing; so does a re-run (a resume at `spec`) when `backlog.md` already has a line containing both `(from $ID)` and `{setup:`. A failing `backlog-add` adds nothing and never stops the job; name it in the final report as `Human setup not parked: <its error>`.
      **Dupe check** (before every `B backlog-add`): when `$F/backlog.md` has an open `- [ ]` line, pipe each new item, every `'` removed, to `python3 ~/.claude/skills/trevskills-scrum/jev-gate.py dupe $F/jobs/$ID` (one call per item, Bash timeout 90000; a BigBoy parent uses `$F/jobs/$P`). On output `dupe <item>`, append ` (possible dupe of <item>)`, every `'` removed, to the text passed to `backlog-add`. The item is always added.
      **Rank** (after the Dupe check, before every `B backlog-add`): pipe each bare item (no suffix), every `'` removed, to `python3 ~/.claude/skills/trevskills-scrum/jev-gate.py rank $F/jobs/$ID` (Bash timeout 90000; a BigBoy parent uses `$F/jobs/$P`). On output `p<N> <kind>`, pass `--priority N` to `backlog-add` (one call per item when ranked items differ in N); on `none`, a failure or a timeout, add it with no flag. When the bare item starts with `Critical:`, also pipe it to `jev-gate.py critical $F/jobs/$ID` the same way; on `critical`, pass `--critical`. backlog-add caps an item with no `--trevor` at p:3.
4. **Worktree:**
   ```bash
   WT="$REPO/.claude/worktrees/scrum-$ID"
   git fetch origin
   git worktree add "$WT" -b "scrum/$ID" "$BASE"
   find "$REPO" -maxdepth 1 -name '.env*' | while read -r e; do git -C "$REPO" ls-files --error-unmatch -- "$(basename "$e")" >/dev/null 2>&1 || ln -sfn "$e" "$WT/$(basename "$e")"; done
   ```
   Run `Install` from `project.md` in `$WT`; never symlink `node_modules` from `$REPO`.
   When `$WT/prisma/schema.prisma` exists, run `npx prisma generate` in `$WT` after the install.
   Then `B set $ID worktree=$WT stage=build`, then **Cool-down park** (merge.md).
5. **Build:** first sync the branch: run `git -C "$WT" fetch origin` then `git -C "$WT" merge "$BASE" --no-edit`. On a merge conflict run `git -C "$WT" merge --abort`, carry on to the builder unmerged (the Merge **Conflicts** step still resolves it). Then spawn `scrum-builder` (see **Routing**) with step 3's **Model:** override and wait for it. Prompt: the 5 lines with `WORKTREE=$WT` and `ROUND=0`, plus `Implement spec.md. Write build.md.` Record the returned agent id/name with `B set $ID builder=<id>`. If `build.md` starts `STATUS: BLOCKED`: when its first reason line names a job on this board (id or number), run `B wait-on $ID <that id>`; on exit 0 run `git -C "$REPO" worktree remove -f "$WT"` and `git -C "$REPO" branch -D "scrum/$ID"` (a child then runs **BigBoy lane** step 6) and stop: serve.py starts it once that job merges. When no job is named or `wait-on` exits non-zero, run `B ask $ID 'blocked: <first reason line>' --kind blocked --a "Send back with a note=rework $ID \"make the most reasonable call on the blocker and record it as a Ruling in build.md\"" --b "Put back on the backlog=abort $ID --requeue" --c "Remove this job=abort $ID --cascade" --title BUILDER_BLOCKED --recommend <key> '<why>'` and stop, with `<first reason line>` rewritten to the **Issue** bar in `lanes/stops.md` with its prefix kept. If the job's `lane` is `debug`, see **Debug lane** instead of this step.
6. Continue: **Cool-down park** (merge.md), then **Check gate**.

## Fast lane

Applies only while the job's `lane` on the board is `fast`. A job with no `lane`, or `lane=standard`, never reads this section. Same builder, same Check gate; then one diff-only code review (plus one UI reviewer when the diff touches UI) and straight to Merge, with no approver.

1. **Promotion (deterministic).** Promoting means running `B set $ID lane=standard` and appending `Promoted to standard: <trigger>` to `$F/jobs/$ID/promoted.md`; the job then continues on the standard path from where it is. A standard job is never set back to fast. You never judge the conditions yourself: run `B route-check $ID` (add `--clean-start` only when this session knows the round was not started by the Merge **Conflicts** step) and promote with trigger = its `promote` field whenever that is non-null; a `null` `promote` means the job stays fast.
   - **2nd check failure:** when `check.md` says `CHECK: FAIL` for the 2nd time in a round, run `B route-check $ID --check-fails 2` (`check.md` is overwritten per attempt, so you pass the count). Its `promote` is then `check failed twice`. The fix attempts in **Check gate** step 4 then carry on as standard.
   - **After `CHECK: PASS`, before Review**, run `B route-check $ID`. It reruns every round, including after the Merge **Conflicts** step sends the job back to the Check gate. It checks, in order, against `git -C "$WT" diff --numstat`/`--name-only "$BASE"...HEAD`: a binary file; more than 100 added lines; more than 10 files with an added line (deleted lines and delete-only files don't count; exactly 100 lines or exactly 10 files stays fast); the Merge schema guard regex or `(^|/)\.env`; then the sensitive-path regex, case-insensitively: `grep -iE '(^|/)(middleware|proxy)\.[cm]?[jt]sx?$|auth|session|login|signin|signup|password|permission|payment|billing|checkout|stripe|webhook|secret|credential'` (trigger `sensitive path <first matching file>`; **Review** step 2's Security skip uses this same regex). A diff it can't read promotes (`diff unreadable`).
2. **Review.** Run `B set $ID stage=review`. The UI reviewer is spawned only when a runtime file (the Check gate's runtime-file rule) matches `UI globs`: `scrum-review-e2e` when `project.md` has an `E2E:` line that isn't `none` and **Review** step 3 does not skip it as already checked, else `scrum-review-ui`. Write `round-$N/review-security.md`, `round-$N/review-ux.md` and `round-$N/review-ui.md` yourself, except the spawned UI reviewer's file, each containing exactly:
   ```
   VERDICT: PASS
   Skipped by orchestrator: fast lane.
   ```
   Unless `scrum-review-e2e` is spawned, first run `rm -f "$F/jobs/$ID/round-$N/review-e2e.md"` (a stale triage file).
   Spawn `scrum-review-code` with the 5 lines (`ROUND=$N`), the line `LANE=fast`, and `Review this round. Write only your own review file.`; in the same message spawn the UI reviewer, if any, with the same lines but no `LANE=fast` and no `DEV_URL` (it starts its own server). Never spawn an approver, security or ux reviewer. Wait for all, then handle `B sync $ID` exactly as **Review** step 4.
3. **Route:**
   - `verdict` is `PASS` (both spawned reviewers passed): go straight to **Merge**. Spawn no approver; there is no decision.md. The PR uses the no-Merge-summary fallback in Merge step 3 (job title, spec acceptance criteria as bullets), and the body line `Approved by the scrum approver. Spec, reviews and decision: scrum/jobs/$ID/` is replaced by `Fast lane: check gate + code review. Spec and review: scrum/jobs/$ID/`. The schema guard still runs unchanged. With no decision.md, the `Restart:` line counts as `none`.
   - `verdict` is `CHANGES` and `round < limit`: resume the builder as in **Review** step 5, run `B set $ID stage=build`, and go to **Check gate**. The job stays fast.
   - `verdict` is `CHANGES` and `round >= limit`: go to **Approve**, as standard does.

## Check gate

If the job's `lane` is `fast`, see **Fast lane** (promotion on the 2nd failure, and before Review). If it is `debug`, step 2 adds the debug checks and step 4 ends differently.

1. `N = round + 1` (round as stored on the board). Run `mkdir -p $F/jobs/$ID/round-$N`, then `B set $ID round=$N stage=check`, then `B check-reuse $ID`: a non-null `reused` has already written `round-$N/check.md` (HEAD unchanged since that PASS), so go straight to step 5. Otherwise, only when `N = 1`, sync with `origin/$DEFAULT` before step 2: run `lanes/merge.md` step 5 **Conflicts** sub-step 1's fetch, HEAD record and merge, then sub-step 3's install check. On a conflict run `git -C "$WT" merge --abort`, do not resume the builder, do not `B ask`, and carry on to step 2 unmerged (**Conflicts** resolves it at Merge). When `N > 1` never sync.
2. **Runtime files** are the lines that survive `git -C "$WT" diff --name-only "$BASE"...HEAD | grep -vE '(^|/)(__tests__|e2e|tests?|docs?)/|\.(test|spec)\.[cm]?[jt]sx?$|\.(md|mdx|txt)$'`; a file the regex does not exclude counts as runtime. In `$WT`, when `$WT/.next/types` exists, run `rm -rf "$WT/.next/types"` first so stale generated types never fail Typecheck; then run each of Test / Typecheck / Lint / Build from `project.md` that isn't `none`; Build runs as `python3 "$HOME/.claude/skills/trevskills-scrum/buildlock.py" --project "$F/project.md"`; Test, Typecheck and Lint each run as `SCRUM_BUILD_LOCK="$HOME/.claude/trevskills-scrum/check.lock" python3 "$HOME/.claude/skills/trevskills-scrum/buildlock.py" '<command>'` (2 at a time across jobs). When Lint is `eslint .` or `npx eslint .`, the `<command>` is `npx eslint --cache <changed .js/.jsx/.ts/.tsx/.mjs/.cjs files>` from `git -C "$WT" diff --name-only --diff-filter=d "$BASE"...HEAD`, the full Lint when the diff touches `eslint.config.*` or `.eslintrc*`, and with no such file Lint does not run: write `Lint: skipped, no lintable file in diff`; any other Lint runs as written. Run the `Test:` command in full as `project.md` states it, with the Bash tool's `run_in_background` when it can outlast the 600 s Bash timeout (CLAUDE.md or `project.md` notes say so), and wait for it to exit; never replace it with one module or a subset, and never take the builder's own run as the result; check.md records the exit code and the last 40 lines of that full run. Test, Typecheck and Lint always run; Build is skipped when there is no runtime file. When `$WT/prisma/schema.prisma` exists, run `npx prisma generate` so a stale client never fails Typecheck. When `project.md` has an `E2E:` line that isn't `none`, run `B e2e-specs $ID` (the specs the diff's UI files map to; `full` on a `- E2E full globs:` hit; the full suite also runs on main from the serve.py watchdog). For `mode` `full` or `scoped`, or for `mode` `none` when a runtime file matches `UI globs` (the UI/UX reviewers render it on dev, which lacks the new columns until Merge), first do merge.md's **Dev migrate (Check gate)** when its condition holds; then, for `full` or `scoped` only, run its `command` as `SCRUM_BUILD_LOCK="$HOME/.claude/trevskills-scrum/e2e.lock" python3 "$HOME/.claude/skills/trevskills-scrum/buildlock.py" '<command>'` with the Bash tool's `run_in_background`, and wait for it to exit (it can outlast the 600 s Bash timeout), which queues it so one E2E runs at a time across jobs; a non-zero exit is `CHECK: FAIL`. For `mode` `none` nothing runs: step 3 writes `E2E: skipped, no spec covers the diff` when `uncovered` is non-empty (at least one runtime file matches `UI globs`, but no spec covers it), else the no-runtime-file skip. A Test, Typecheck, Lint or E2E run (or its retry) that exits 124 timed out waiting for the lock, not on the code: re-run it once through the same lock; a second 124 is a capacity wait, not a failure: run `B ask $ID 'waiting on the E2E queue' --a "Carry on=resume $ID" --b "Remove this job=abort $ID --cascade" --title CHECKS_FAILING --recommend <key> '<why>'` (for `check.lock`, `'waiting on the Check queue'`; board.py turns that question into a stall, not a stop; it stalls the job in check: no `CHECK:` verdict, never needs-human) and stop; the watchdog resumes it into this step. Run `git -C "$WT" diff --name-only "$BASE"...HEAD | grep -E '(^|/)\.env'`; any output is a failure ("committed .env file").
   For `lane=debug`, also run these; each failure makes `CHECK: FAIL` and gets its own entry in check.md:
   - **Repro:** the `Repro:` command from `assessment.md`, in `$WT`. It must exit 0.
   - **Allowed files:** every path in `git -C "$WT" diff --name-only "$BASE"...HEAD` must be listed under `## Allowed files` or be the `Repro test:` path. Otherwise it fails with `outside allowed files: <path>`.
   - **Repro test untouched:** `git -C "$WT" diff --name-only <Commit from repro-before.md> HEAD -- <Repro test path>` must print nothing. Otherwise it fails with `repro test changed`.
   When Lint exits non-zero and every error is in a file outside `git -C "$WT" diff --name-only "$BASE"...HEAD`, record it in check.md as `Lint: pre-existing, no error in diff files`; it alone does not make `CHECK: FAIL`, and the approver still adds its Follow-up.
   When Test exits non-zero and every failing test file is outside that diff, re-run only those files once. A file that passes on the retry is recorded in check.md as `Test: pre-existing, <file> passes alone`. Run each file that still fails on unmodified `$BASE`: run `git -C "$WT" worktree remove -f "$WT-base"` and ignore any error, then `git -C "$WT" worktree add --detach "$WT-base" "$BASE"`, run `Install` in `$WT-base`, symlink the untracked .env* files from `$REPO` with the new-job command (not the tracked ones), run `npx prisma generate` in `$WT-base` when `$WT-base/prisma/schema.prisma` exists, run only that file, and remove it with the same remove command. A file that fails on `$BASE` too is recorded as `Test: pre-existing, <file> fails on $BASE`. A `pre-existing` line alone does not make `CHECK: FAIL`, and the approver still adds its Follow-up. A file that fails on the retry and passes on `$BASE` makes `CHECK: FAIL`, and so does one the gate cannot compare: a setup error is `CHECK: FAIL` like an Install failure, never `fails on $BASE`.
   When Build exits non-zero on a failed network fetch (like Google Fonts), or the Bash tool's time limit killed it, re-run it once (after a time-limit kill, with the longest timeout) and record the retry and result in check.md.
   When the E2E command exits non-zero and every failing spec is outside that diff, re-run only those specs once through the same E2E lock (`npx playwright test --workers=1 <spec files>`, same `E2E_PORT`) and record a spec that passes on the retry in check.md as `E2E: pre-existing, <spec> passes alone`; that line alone does not make `CHECK: FAIL`, and the approver still adds its Follow-up. A spec that still fails on the retry, when an open `- [ ]` line in `$F/backlog.md` names that spec file and each of its failing tests (by title or line), is recorded as `E2E: pre-existing, <spec> on backlog` and never re-run on `$BASE`; that line alone does not make `CHECK: FAIL`.
3. Write `round-$N/check.md`: first line `CHECK: PASS` or `CHECK: FAIL`, then for each command its exit code and the last 40 lines of output in a fenced block. A command step 2 skipped writes `E2E: skipped, no runtime file matches UI globs` (or the no-spec skip above) or `Build: skipped, no runtime file in diff` in place of its exit-code block; a skip never makes `CHECK: FAIL`. Whenever E2E ran, add the line `E2E specs: <spec files>|all` (`all` for `mode` `full`).
4. If it says FAIL, resume the builder (see **Sonnet promotion**) with `Checks failed: read JOB_DIR/round-N/check.md, fix, commit, update build.md.` **E2E triage:** when the E2E command from step 2 ran and exited non-zero, first spawn `scrum-review-e2e` with the 5 lines (`ROUND=$N`) plus `Triage the failing E2E run. Write only your own review file.`, and wait for it; then the resume message is `Checks failed: read JOB_DIR/round-N/check.md and JOB_DIR/round-N/review-e2e.md, fix, commit, update build.md.` instead. Then re-run steps 2–3, overwriting `check.md`. Allow up to **3** fix attempts. If it still fails, skip the review and go to **Approve**; the approver rules on the failing check. Exception: a `lane=debug` job that still fails after the 3rd fix attempt never goes to **Approve**: run `B ask $ID "debug: three fixes in a row did not make the failing test for this bug pass, so the diagnosis may be wrong." --kind check-fail --a "Send back with a note=rework $ID \"three fixes failed: re-read assessment.md, question the root cause and try a different fix\"" --b "Remove this job=abort $ID --cascade" --title CHECKS_FAILING --recommend <key> '<why>'` and stop.
5. If it says PASS, go to **Review**.
