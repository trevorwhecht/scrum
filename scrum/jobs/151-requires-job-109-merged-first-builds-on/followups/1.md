# Delete a stale review-e2e.md when the e2e reviewer is not spawned
UI surface: no
Hard stops: none
Lane: fast

## Problem
**How the stale file arises.** Check gate step 4 (E2E triage) spawns `scrum-review-e2e` when the E2E command fails. That agent writes `round-N/review-e2e.md`. If the builder's fix then removes every `UI globs` file from the diff, two things happen:
- Review step 3 no longer spawns `scrum-review-e2e`.
- Fast-lane step 2 never spawns it at all.

**Why it matters.** The triage file stays in the round folder anyway. `board.py sync` counts any `review-e2e.md` that is present. So a stale `VERDICT: CHANGES` (for example, a `real bug` verdict the builder has since fixed) still forces the round verdict to `CHANGES`.

**Where it came from.** The code review of job 151 found this (review-code finding 1, minor) and the approver deferred it.

## Scope
In:
- Add a deletion rule to `skills/trevskills-scrum/SKILL.md` at two points:
  - **Review** step 3;
  - **Fast lane** step 2.

  Both run before any reviewer is spawned. When `scrum-review-e2e` is not being spawned this round, the orchestrator runs `rm -f "$F/jobs/$ID/round-$N/review-e2e.md"`.
- Add one contract-test assertion.

Out:
- Changes to `board.py sync`.
- Renaming the triage file. The triage output stays `review-e2e.md`, because the builder's resume message names that file.
- Changes to the Check gate triage itself.
- Changes to the path where Check gate fails 3 times and goes to Approve. There the triage file is kept, so the approver can read it.

1. **Review step 3.** The step states: when `scrum-review-e2e` is not spawned this round, delete `round-$N/review-e2e.md` before spawning the other reviewers. The not-spawned cases are:
   - `project.md` has no `E2E:` line, or the line is `none`;
   - no file in the diff matches `UI globs`.

   (verify: extend `test_skill_wires_e2e_reviewer` in `tests/test_contracts.py`. It asserts that the `## Review (WAIT FOR ALL)` section contains `rm -f` on the same line as `review-e2e.md`.)
2. **Fast lane step 2.** The step deletes `round-$N/review-e2e.md` before spawning `scrum-review-code`. (verify: new test `test_fast_lane_deletes_stale_e2e_review`. It asserts that the `## Fast lane` section, up to `## Debug lane`, contains `review-e2e.md` and `rm -f`.)
3. **Spawned path unchanged.** When `scrum-review-e2e` is spawned in Review step 3, nothing is deleted first. The existing text stays: the agent overwrites the triage file. (verify: manual read of Review step 3. The `test_skill_wires_e2e_reviewer` assertions that existed before this change still pass.)
4. **Tests pass.** `python3 -m unittest discover -s tests` passes. (verify: run the command.)
